# status-updates

Report observed progress, the work in flight and the next resolving action. Distinguish finished evidence from intended work so another contributor can resume accurately.

Owned scope: `repo-hygiene.status-updates`. Input: `rig-services/development.repo-hygiene.status-updates.json`.

Coverage ceiling: Configuration validation only, so it confirms completed work, in-flight work and a next action are written; it does not show the status is accurate.

minimal: completed — ["parser regression reproduced"]. List what is completed with evidence. Mixing intent with finished work misleads the reader, so record only done items.

mid: in flight — ["shared boundary fix"]. List the work in flight. Another contributor cannot resume without it, so name the open tasks and who holds them.

maximal: next action — "run parser regression". State the next resolving action. A status without a next step leaves the work stalled, so write the single action that moves it forward.
