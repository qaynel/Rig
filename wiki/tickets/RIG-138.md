# RIG-138 — AT-LF-20 approval `.used` flag is in-memory only; evaporates across process boundaries

**Class: CORRECTNESS / SHELL TRUST.**
**Status: COMPLETE (2026-08-28) — GitHub #93.**
Ticket: RIG-138 on [[Tickets]].

## Resolved (2026-08-28)

`consumePlanApproval` in `rig/lib/lint-format.js` now writes a durable,
exclusive-create (`wx`) record to `<target>/.rig/lint-format/executions/
<digest(plan_digest)>.json` before `executePlan` marks the in-memory
`approval.used`; a second presentation of the same `plan_digest` (a fresh
approval object, a different process) hits the existing record and returns
`not_authorized`, matching every acceptance criterion below. Verified: the
named `AT-LF-20` oracle case and `tests/guarantee-coverage.test.js`'s
`AT-PROC-1a` (independent approval object, not just in-memory identity) are
both green on current HEAD. Board entry was left OPEN after this landed;
corrected during a later triage pass.

## Problem

`executePlan` in `rig/lib/lint-format.js:459` enforces the AT-LF-20 single-use
guarantee by setting `approval.used = true` on the JS object it receives. That
mutation lives only in the calling process's heap. When the process exits — the
normal case in a real plan/execute flow, where planning and execution are
separate agent turns — the flag is gone.

A new process that receives the same approval object (from a file, a tool call
output, a clipboard paste) sees `used: false` and will execute the plan again
without objection. The one-execution-per-approval guarantee the acceptance case
requires is therefore not durable; it holds only within a single process run.

## Location

`rig/lib/lint-format.js` — `executePlan`, line 459:

```js
approval.used = true;
```

No persistence follows this line. The flag is checked at line 439 (`if
(approval.used)`) but only if the same in-memory object is passed back, which
never happens across a process boundary.

## Acceptance (draft — not yet reviewed or signed off)

- An approval consumed by one `executePlan` call is refused by a subsequent
  call even when the process has exited and restarted between the two calls.
- The consumed state is recorded in a durable location (e.g. an on-disk receipt
  keyed by `plan_digest`) and checked before execution.
- A replay attempt on a persisted approval returns `not_authorized`, matching
  the existing in-process behaviour.
- A new test title covering the cross-process case is added to
  `tests/advanced-oracle.test.js` (or equivalent) before any implementation
  lands.
