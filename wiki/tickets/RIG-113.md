# RIG-113 — Bound the lint-format setup/replacement (hybrid-plus) contract

**Status: BLOCKED (2026-08-24) — GitHub #65 — needs owner approval of the ranked policy and
backup convention before acceptance can freeze.**
Ticket: RIG-113 on [[Tickets]].

## Problem
The hybrid-plus promise (catalogue-contract topic): Rig preserves/adapts to the
repo's toolchain, may offer one if none exists, and may propose a "better
supported alternative" — but the exact meaning of "better" and the generated
setup contract are unbounded.

## Findings
`GA-16` fixes hybrid-plus as the product promise; `GA-19` makes ecosystem
applicability repository-derived. The open piece is purely the **decision rule**
for proposing a replacement and the **generated-setup contract**, both to be
bounded in the lint-format grilling (owner-authored acceptance).

## Solution (proposed testable rule)
1. **"Better alternative" = a bounded, ranked rule, never taste.** Propose a
   replacement only when the repo's current tool is (a) unmaintained/EOL per a
   declared signal, (b) unable to cover a component the user selected, or (c)
   absent entirely. Ranking uses a fixed, declared preference list per ecosystem
   (recorded in the leaf), not model discretion. Any proposal is a **suggestion
   requiring explicit user decision** — it never lands silently.
2. **Generated-setup contract**: specify exactly which files it writes (config +
   ignore only), the scope (selected components), and that it is gated behind an
   explicit approval distinct from selection and from plan approval (ties to
   [[RIG-115]] execution consent). No mutation without that approval.
3. **Acceptance cases**: (i) existing good tool → preserved, no proposal; (ii)
   EOL tool → proposal surfaced, declined → nothing written; (iii) no tool,
   approved setup → exactly the specified files land; (iv) proposal accepted for
   a replacement → old config preserved/backed up, not deleted.

## Owner input
The preference-list contents and the definition of the EOL/coverage signals are
product decisions to freeze in the lint-format grilling. I can draft the ranked
lists and acceptance; landing them re-signs Gate 1 (see [[RIG-115]], [[RIG-102]]).

## Blocker record (2026-08-24)

The requested drafts already exist in `specs/ecosystem-preferences.md` and
`specs/setup-decision-rule.md`: five ranked ecosystems, explicit EOL/coverage
signals, three proposal conditions, exact write scopes, and a distinct user
approval rule. They are not acceptance-ready because the owner has not approved
those preference contents, and the setup draft explicitly marks
`<file>.rig-backup` as an assumption that must be reconciled with Rig's existing
git/preimage lifecycle. No runnable acceptance case covers this contract.

To unblock, the owner must approve or amend the ranked lists/signals and choose
the replacement backup behavior. The agent can then author the deterministic
cases, add them to the oracle under the owner's re-signing ceremony, and
implement against that frozen boundary. Implementing the draft now would make
agent-authored taste into product policy, so no code was changed.
