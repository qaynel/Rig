## Capability-policy close-out (2026-08-29)

The canonical runner now applies every approved capability control to both the
interactive and installed CI paths. Every command receives the default 10
minute / 2 GiB ceilings unless a binding requests a valid alternative; the
watchdog reports timeout or memory excess distinctly and kills a timed-out
process tree. Network is explicit `none`, explicit `required`, or visibly
diagnosed `undeclared` compatibility mode. An elevated network or resource
request runs only when the exact service has a sufficient, clean committed
grant in target-owned `.rig/execution-policy.json`; invalid, dirty, missing,
or insufficient policy is a named refusal. The installer writes the memory
watchdog and a user-owned empty policy seed for every profile.

`AT-CAP-1` through `AT-CAP-5` were each first observed failing, then passing
through the source runner and a temporary materialization of the actual
`.rig/bin` / `.rig/lib` layout. The complete non-frozen guarantee suite and
`npm run test:code` are green. [[reasoning/2026-08-29-rig120-capability-policy-close-out]]

## Symlink-escape and checks.js containment fix (2026-08-29)

Fixed the `AT-LF-24` symlink-escape gap the fresh review found: `planExecution`
silently left an escape unmarked and `executePlan` re-read the escaping file a

release still needs a fresh independent review receipt bound to the final
