## Why this ticket exists

The v5.1 migration plan ([[RIG-132]], Expand → Migrate → Contract) defers the
semantic-model collapse past the release. That deferral is only legitimate if
the deferred set contains no defect that is **observable in a capability v5.0.0
claims to support**. Otherwise "defer the architecture" quietly becomes "ship
known-wrong behaviour."

So the deferral needs a gate, and this is it.

## 134.1 (BLOCKER, confirmed) — `contractFor` writes host descriptors that contradict shipped decisions

Shipping chain, traced 2026-08-25:

```
rig/materialize.js
  → lib/cli-advanced.js  runAdvanced
    → lib/apply.js       applyPlan            (:197)
      → materializeHostAdapters               (:435)
        → contractFor    (host-capabilities.js:223)
          → writes .rig/host-contracts/<host>/<axis>.json  into the user's repo
```

`rig apply` is user-invoked — `rig/bootstrap.sh:131` prints it as the install
sequence. `contractFor` reads `REGISTRY` **directly**, so `AUTO_WRITE_OVERRIDE`,
`FILE_OVERRIDE` and `LEGACY_FILE` (`mcp-hosts.js:18-25`) never reach the emitted
descriptors.

Confirmed instances are already written up as [[RIG-128]] 128.1–128.3. The
sharpest is **128.2**: for antigravity the descriptor advertises
`config_scope: repo`, `path: .agents/mcp_config.json`, contradicting RIG-105's
owner-approved manual-only decision and the manual note pointing users at
`~/.gemini/config/mcp_config.json`. An agent that trusts the emitted contract
looks in the wrong place.

**Fix as a leaf fix**: route `contractFor` through the interpreted host
semantics so the descriptors agree with the write path. This is explicitly *not*
the collapse — it is the temporary arrangement that the v5.1 Expand → Migrate →
Contract work replaces structurally.

## Low-context implementation packet — 134.1 only

**Scope.** This ticket closes the shipped descriptor mismatch only. Do not
delete `materializeSelectedHosts`, move the raw registry, or begin the v5.1
semantic-model migration. Those are recorded debt. The live path is
`applyPlan` → `materializeHostAdapters` → `contractFor`; the test must execute
that path by materializing descriptors into a fresh target.

**Chosen representation.** Add one normalized MCP descriptor value to the
interpreted MCP table and make `contractFor` consume it. The descriptor must
state the action Rig actually takes, rather than the raw vendor capability:

| Host class | Required descriptor result |
|---|---|
| Auto-written repo host | `emission: emitted`, `config_scope: repo`, `output.path` and `output.key` equal the renderer's file and key, `auto_write: true`. |
| Antigravity | `emission: emitted`, `config_scope: manual`, `output.path: ~/.gemini/config/mcp_config.json`, `output.key: mcpServers`, `auto_write: false`. No repo MCP file is advertised. |
| pi | `emission: unsupported`, `auto_write: false`, no writable config path. A pre-existing legacy file remains user-owned and is not an output contract. |

CodeWhale is the regression anchor: despite its raw user-global capability, the
shipped write contract is repo-local `.codewhale/mcp.json` with `mcpServers` and
`auto_write: true`. Keep the current raw-registry fields for research; the
normalized value is the only source this pre-v5 descriptor writer may read.

**Tests to write first.** Create `tests/host-contract-parity.test.js`. Use
`materializeHostAdapters` on a temporary target and read the emitted
`mcp_config.json`; compare it against the interpreted MCP record, never against
a second copy of the raw registry.

| Test title | Setup | Required assertion |
|---|---|---|
| `every emitted MCP descriptor agrees with the interpreted write contract` | Iterate every registry host and materialize its descriptor | For every emitted MCP axis, disposition, auto-write flag, path, and key equal the normalized MCP record. |
| `antigravity advertises only the manual global setup` | Fresh target, antigravity descriptor | It contains the manual global path/key and `auto_write: false`; neither `.agents/mcp_config.json` nor repo scope appears. |
| `codewhale advertises the repo redirect used by the writer` | Fresh target, codewhale descriptor | It contains `.codewhale/mcp.json`, `mcpServers`, repo scope, and `auto_write: true`. |
| `pi does not advertise a writable MCP file` | Fresh target plus a user-created `.omp/mcp.json` | Descriptor is unsupported; the user file remains byte-identical. |

The first test must fail on current code because Antigravity and CodeWhale are
derived from raw `REGISTRY`. Do not make it pass by changing the test's expected
values or by special-casing the test hosts.

**Completion command.** Run `node --test tests/host-contract-parity.test.js`
and `node --test tests/advanced-hosts.test.js tests/basic-renderers.test.js`.
Then run `npm test`. The final ticket evidence must name the first parity test.
