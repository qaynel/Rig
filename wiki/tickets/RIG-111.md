# RIG-111 — Define exact user-global MCP contracts + byte-landing tests

**Status: COMMITTED (2026-08-24) — landed on this branch.**
Commit.**
Ticket: RIG-111 on [[Tickets]].

## Problem
The user-global-writes topic says the host registry still needs exact contracts
for every axis whose MCP/other config is user-global: windsurf/Devin Desktop,
cline, hermes, codewhale — where Rig writes outside the repo (`~/.codeium/…`,
cline_mcp_settings, `~/.hermes/…`, `~/.deepseek/…`). No exact merge/preservation
contract or landing test exists.

## Findings
- `host-coverage-spec §3.2` classes these as `mcp: 'user_global'` — "advisory
  note only; vendor ships no per-repo file." So today Rig only *notes* them; the
  gap is that when Rig *does* write user-global config, there is no merge-preserve
  contract or uninstall attribution test.
- `rig/lib/global-writes.js` exists (a user-global writer) and
  `install-manifest.jsonl` is the lifecycle authority; uninstall already removes
  install-ID-attributed global entries (status.md). So the machinery exists; the
  per-axis **contracts + byte tests** are what's missing.

## Solution (per user-global axis)
For each of windsurf/Devin Desktop, cline, hermes, codewhale:
1. **Documented contract**: exact file path, JSON/settings shape, the `key` the
   Rig entry lives under, and the merge rule (place Rig's server, preserve every
   unrelated server/setting byte-for-byte, idempotent re-apply).
2. **Idempotent writer**: route through `global-writes.js` using the shared
   disposition map from [[RIG-104]]; attribute each entry with the install ID so
   uninstall can find exactly its own writes.
3. **Byte-landing test**: seed a fake home with pre-existing unrelated user
   config, apply, assert the Rig entry landed and unrelated config is untouched;
   re-apply, assert no-op; **uninstall**, assert only Rig-attributed entries are
   removed and the rest survive (acceptance bullet 2).

## Sequencing
Depends on the [[RIG-104]] disposition/merge single source of truth. Uses the
same test harness shape as the repo-scope merge tests. Ties into the
[[RIG-110]] evidence bundle for these four hosts.

## Resolution (2026-08-24)

- `rig/lib/global-writes.js` carries dated, cited contracts for Windsurf/Devin
  Desktop legacy Cascade, Cline IDE, Hermes, and CodeWhale. Each uses a
  vendor-visible `rig-<install-id>-<server-name>` key.
- The shared writer preserves unrelated settings and servers, replaces the
  same attributed entry idempotently, and fails unchanged on malformed or
  incompatible input. Hermes uses bounded sentinel-managed YAML because no
  YAML dependency is installed; unsupported shapes fail closed.
- Both uninstall implementations recognize `global-mcp` ledger entries,
  verify the exact current-home path and current owned value, remove only that
  repository's entry, and retain unsafe or changed records for recovery.
- `tests/global-mcp-writes.test.js` covers all four byte landings, repeat
  apply, multi-repository coexistence, exact attributed removal, malformed
  input, and a forged out-of-contract ledger path.
- Activation is deliberately unchanged: the frozen Basic oracle keeps these
  hosts note-only until RIG-110 decides the roster and supplies real-wire
  evidence. This ticket supplies the accepted writer contract, not consent to
  promote an unverified host.

Fresh review added fail-closed validation for empty sanitized identifiers,
unknown ledger kinds, malformed ledgers, incompatible Hermes YAML, changed
owned values, and out-of-contract paths. Final verification: signed 68-case
oracle, 422 root tests, 15 pi-extension tests, and 6 rig-mcp tests all pass.
