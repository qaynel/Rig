# RIG-155 — Real-`npm` clean-container E2E of the customer install path

**Class: TEST INFRASTRUCTURE / COVERAGE GAP (no code yet).**
**Status: OPEN (proposed 2026-08-31) — follow-up from [[RIG-154]].**
Ticket: RIG-155 on [[Tickets]].

## Problem

`AT-HOME-1` (`tests/advanced-oracle.test.js`) proves the installed `rig-mcp`
server boots and answers a real MCP tool call — but only after a **fake `npm`**
on `PATH` copies a pre-built `node_modules` tree into place
(`cp -R "$RIG_TEST_MCP_NODE_MODULES" "$dest/node_modules"`). [[RIG-154]]
deliberately kept that fixture: its scope was "make `npm test` pass on a fresh
checkout", not "prove the customer install".

Nothing in the suite exercises the actual customer path end to end:

- real `install.sh --openclaw-mcp` (no `npm` shim),
- real `npm ci` resolving `rig-mcp/package-lock.json` against a live registry,
- the installed server process actually starting,
- a real MCP client completing a `rig_instructions` call against it,
- in a clean container with no ambient `node_modules` / caches.

So a break anywhere in that chain — a bad lockfile, a postinstall failure, a
packaging path that only works with the staged copy — would ship undetected by
CI.

## Why it is its own ticket

Running a real networked `npm ci` inside the unit suite is explicitly
disallowed (RIG-154 design, §D2): it would make every `npm test` slow and
registry-dependent. This E2E therefore needs its own opt-in job (nightly / a
dedicated workflow / a `test:e2e` script), not a case in the signed oracle.

## Required shape (to be designed)

- A container or fresh VM with only Node + a package registry reachable; no
  repo `node_modules`, no `.venv`, no npm cache warmed by earlier steps.
- Run the published install path against a checkout of the repo (or the packed
  tarball, if that is the shipping vehicle).
- Assert: `install.sh` exits 0; the MCP server process is listening; a real
  client call returns the expected `rig_instructions` payload; uninstall
  reverses it.
- Wire it to run on a schedule or pre-release, not on every push. Record the
  registry, Node version, and repo SHA with each run.
