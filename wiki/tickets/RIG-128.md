## Problem

The MCP merge writer (`mergeMcpEntry`/`setAtPath`) is idempotent and
sibling-preserving for every well-formed shape (verified), and the user-global
attributed writer/remover is clean. Two real defect classes remain: the emitted
host-contract descriptors **advertise a location/scope Rig does not actually
use**, and the repo-local merge writer **silently clobbers** malformed or JSON5
files. The path-divergence half shares its structural root with [[RIG-125]]; the
concrete per-host corrections and the write-safety bug live here.

## Sub-findings

- **128.1 (High) — codewhale: the two paths disagree on file and scope.**
  `renderers.js` auto-writes repo `.codewhale/mcp.json` (via `FILE_OVERRIDE`
  `mcp-hosts.js:19` + `AUTO_WRITE_OVERRIDE:18`), but the emitted host-contract
  (`materializeSelectedHosts` :342-346 → `.rig/host-contracts/codewhale/…`)
  declares MCP is `user_global` at `~/.deepseek/mcp.json`. An agent that trusts
  the emitted contract looks in the wrong place. *(Delivery itself works —
  verified: CodeWhale reads both `servers` and `mcpServers`, and honors
  `DEEPSEEK_MCP_CONFIG=./.codewhale/mcp.json`; default `~/.codewhale/mcp.json`,
  fallback `~/.deepseek/mcp.json` — github.com/Hmbown/CodeWhale docs/MCP.md. So
  this is a contract-accuracy defect, not a broken write.)*
- **128.2 (High) — antigravity: the descriptor advertises a repo auto-write that
  never happens.** RIG-105 makes it manual-only (`AUTO_WRITE_OVERRIDE.antigravity
  = false`), yet `materializeSelectedHosts('antigravity').mcp = {status:'repo',
  path:'.agents/mcp_config.json'}` and the emitted axis says `emission: emitted,
  config_scope: repo`. The descriptor contradicts the shipped owner decision and
  the manual note pointing users to `~/.gemini/config/mcp_config.json`.
- **128.3 (Medium) — codewhale is described in three inconsistent locations:**
  `~/.deepseek/mcp.json` (`host-capabilities.js:123`), repo `.codewhale/mcp.json`
  (renderers + `credentials.js:11` redirect), and `~/.codewhale/mcp.json`
  (`global-writes.js:27`). Nothing reconciles them. (Disposition decision is
  RIG-110's; the code-level triplication is fixed here.)
- **128.4 (High/Medium) — OpenClaw repo auto-write clobbers a JSON5 surface.**
  `REGISTRY.openclaw.scope='repo'` auto-writes repo `.openclaw/openclaw.json` via
  `mergeJson` (`renderers.js:11-23`), which `JSON.parse`s the file and, on any
  parse error, **resets `obj={}`** (`:17`) — silently discarding user content.
  But OpenClaw's real surface is JSON5 (comments/trailing commas) managed by
  `openclaw mcp set` (verified: docs.openclaw.ai/cli/mcp; servers nest under
  `mcp.servers`). A JSON5 file at the repo path is destroyed. The safe user-global
  opt-in ([[RIG-123]], native CLI) and this naive repo path disagree on format
  safety, and `scope='repo'` sits uneasily with the verified user-global surface.
- **128.5 (Low/Medium) — the repo merge writer is strictly less safe than the
  global one.** `mergeJson` (`renderers.js:14-20`) swallows a parse error and
  overwrites (silent data loss), whereas `global-writes.js:118-121` throws
  `invalid JSON … left unchanged`. `setAtPath` (`renderers.js:43-48`) is
  non-strict and would silently drop the entry if a dotted-path key holds a
  non-object primitive.
- **128.6 (Low) — internal table inconsistencies.** `MCP_HOSTS.hermes.key =
  'mcpServers'` disagrees with `GLOBAL_MCP_CONTRACTS.hermes.server_key =
  'mcp_servers'` and the YAML surface (`global-writes.js:23`) — harmless only
  because hermes is `autoWrite=false`. Cline is cited to two different URLs
  (`host-capabilities.js:110` vs `global-writes.js:18`) — see [[RIG-129]].

## Why it matters

Emitting a host-contract that names the wrong file/scope actively misleads any
agent that consumes it (the contracts exist precisely so agents can trust them),
and the JSON5 clobber is silent user-data loss on install — the opposite of the
"preserve unrelated bytes" contract.

## Recommended direction

Make the emitted descriptor derive from the same single disposition authority as
the renderer ([[RIG-125]]) so it can never advertise a scope/file the writer
doesn't use; make the repo merge writer fail-closed on unparseable input like the
global one, and route JSON5 hosts through a JSON5-safe read or the native CLI
rather than `JSON.parse`. Reconcile the codewhale/hermes table values.

## Low-context implementation packet

**Scope.** Implement the descriptor parity through [[RIG-134]] first. This
ticket owns only the repository merge writer's data-loss boundary afterwards.
Do not add a JSON5 package simply to parse a file if the writer can refuse the
operation safely. A failed install that leaves user bytes unchanged is correct;
a successful install that rewrites unknown syntax is not.

**Production seam.** `mergeJson` is the only JSON-shaped repository merge entry
point. Change it once, then have `setAtPath` reject a non-object intermediate
instead of replacing it. On failure, throw an error that includes `left
unchanged`; callers must propagate that error and must not write the file.

**Tests to write first.** Create `tests/repo-mcp-write-safety.test.js`. Exercise
`renderMcp` or `mergeMcpEntry` against files on disk, then compare original bytes
after the call. Do not mock `fs.writeFileSync`; data preservation is the behavior.

| Test title | Seed file | Required assertion |
|---|---|---|
| `an invalid repository MCP file is left byte-identical` | Malformed JSON containing unrelated text | The write throws `left unchanged`; bytes are exactly the original bytes. |
| `an OpenClaw JSON5 file is never clobbered` | `.openclaw/openclaw.json` with a comment and trailing comma | Either the configured JSON5-safe writer preserves unrelated data and adds the server, or it throws without changing one byte. Parsing as JSON then overwriting is forbidden. |
| `a primitive dotted-path segment is rejected without a write` | OpenClaw JSON with `{"mcp": true}` | The write throws; `mcp` stays boolean and the whole file is byte-identical. |
| `a valid repository MCP merge preserves unrelated content and is idempotent` | Valid nested OpenClaw config with unrelated sibling entries | Existing sibling bytes/values survive, the desired server is present once, and a second run is byte-identical. |

The first three tests must fail on current code. Keep the existing
`basic-mcp-merge` coverage; it proves the valid-shape contract, while this file
proves no user data is destroyed when the shape is unsafe.
