## Problem

A ticket reaches **Done** on the board when an agent writes a `**Done:**`
paragraph describing what it did. Nothing checks that paragraph against the
repository.

Three cards moved that way and are unmet in shipped code:

- **[[RIG-104]]** claims *"Both `renderers.js` (legacy Basic path) and the
  catalogue descriptor path now read it."* Verified 2026-08-25: only
  `renderers.js` imports `MCP_HOSTS`; `materializeSelectedHosts`
  (`host-capabilities.js:331-353`) reads `REGISTRY` directly and never applies
  `AUTO_WRITE_OVERRIDE` / `FILE_OVERRIDE` / `LEGACY_FILE`.
- **[[RIG-107]]** claims bootstrap prints a copy-pasteable
  inspect→recommend→plan→apply→check workflow. The printed commands need
  `review.json`, `rig.json` and `approval.json`, none of which any printed step
  produces, and the "host review" stage is not a subcommand at all.
- **[[RIG-105]]** claims the Antigravity manual MCP step is first-class. It is
  rendered only by the legacy Basic path (`materialize.js:50`), never by the
  staged `--with-runtime` onboarding a real user follows.

All three were green on the full gate the whole time. The gate had nothing to
say about any of those three claims, because no test encodes them.

## Why this is structural

`Done` is currently a *description* of work. The reviewer checks the *product*.
When the description and the product disagree, the review finds it — every time,
forever, because nothing else can. Converting `Done` into an executable
assertion is what makes the board and the product the same object.

Note the interaction with [[RIG-125]]: adding property tests without this check
means the next batch of cards can go Done on prose again, against tests that were
never named. The two are cheap together and weak apart.

## Recommended direction

1. **Convention.** Every ticket file's `## Acceptance` bullets each end with
   `→ <test file>::<test name>` (or `→ manual: <why no test is possible>`, which
   is allowed but counted).
2. **Checker.** `scripts/check-ticket-traceability.js`:
   - parse `wiki/Tickets.md` for cards in **Done** / **Ready for Commit**;
   - open each linked ticket file, read its acceptance bullets;
   - fail if a bullet names no test, names a test file that does not exist, or
     names a test name not found in that file;
   - report the `manual:` count separately so it stays visible rather than
     becoming the escape hatch.
3. **Wire it into `npm test`** next to `check-rule-copies.js` and
   `check-versions.js`, so a Done card that stops being true breaks the gate.
4. **Work the initial violation list.** A Done card that cannot name a test moves
   back to Backlog with the reason. This is the re-verification [[RIG-125]] asks
   for, mechanised.

## Acceptance

- `scripts/check-ticket-traceability.js` exists and runs inside `npm test`.
  → `tests/ticket-traceability.test.js::traceability checker runs from npm test`
- A Done card whose acceptance bullet names no test fails the gate.
  → `tests/ticket-traceability.test.js::a completed card without an evidence reference fails`
- A Done card naming a test that does not exist, or a test name absent from the
  named file, fails the gate.
  → `tests/ticket-traceability.test.js::a missing file or missing named test fails`
- Deleting or renaming a test that a Done card depends on fails the gate.
  → `tests/ticket-traceability.test.js::the checker rejects a stale test title`
- The `manual:` escape count is printed on every run.
  → `tests/ticket-traceability.test.js::manual evidence is counted and reported`
- The initial violation list is worked: every remaining Done card names a real
  test, and cards that cannot are back in Backlog with a stated reason.
  → `tests/ticket-traceability.test.js::the current board has no unresolved completed-card violation`

## Low-context implementation packet

**Outcome.** A completed card is evidence, not an agent summary. The release
gate must fail before code tests whenever a card in the board's completed
columns cannot point at a present, runnable test.

**Do not change.** Do not edit the owner-signed oracle, infer test references
from a `Done:` paragraph, or accept a bare filename. The evidence must be in a
ticket's `## Acceptance` section and name both a test file and its exact test
title. `manual:` is permitted only where automation is impossible; it is visible
output, never a silent pass.

**Implement in this order.**

1. Add `scripts/check-ticket-traceability.js`, with no dependencies. Its default
   inputs are `wiki/Tickets.md` and `wiki/tickets/`; support `--board <file>` and
   `--tickets <dir>` solely so the unit test can use temporary fixtures.
2. Parse board cards only from `## Done` and `## Ready for Commit`. Follow their
   Markdown solution link to the matching ticket. Do not scan prose elsewhere
   in the board.
3. Read each `## Acceptance` section as a list of bullets. Every bullet must end
   in either `→ tests/<file>.test.js::<exact title>` or `→ manual: <reason>`.
   Reject a missing reference, a non-existent test file, or a title not present
   in the named file. A text search for the title is sufficient; this checker
   validates traceability, while Node's test runner validates executability.
4. Print one line per violation, then `manual evidence: <count>`. Exit non-zero
   iff there is at least one violation. Wire it before the Node test glob in
   `test:code`, so the source test suite never hides a false completion claim.
5. Run the checker against the real board. Move cards that cannot supply a
   current test back to Backlog; do not invent an evidence line to preserve a
   completed status.

**Tests to write first.** Create `tests/ticket-traceability.test.js` using a
temporary board plus temporary ticket files. Each case runs the script as a
child process, not its internal helpers:

| Test title | Fixture | Required result |
|---|---|---|
| `traceability checker runs from npm test` | Real repository inputs | `npm test` invokes the script before Node tests; the script exits zero only after the real board is repaired. |
| `a completed card without an evidence reference fails` | One Done card linked to a ticket with a plain acceptance bullet | Non-zero exit and output naming that ticket and the missing reference. |
| `a missing file or missing named test fails` | First reference names no file; second names an existing file with another title | Non-zero exit and both diagnostics. |
| `the checker rejects a stale test title` | Existing test file whose prior title no longer occurs | Non-zero exit and the stale title in output. |
| `manual evidence is counted and reported` | One valid test reference plus one `manual:` bullet | Zero exit and exactly `manual evidence: 1`. |
| `the current board has no unresolved completed-card violation` | Actual board and ticket directory | Zero exit, after any card without current evidence is moved out of a completed column. |

**Completion command.** Run `node --test tests/ticket-traceability.test.js`,
then `npm test`. Record the named green test next to this ticket's Done claim;
do not move another card to Done until its own reference is present.
