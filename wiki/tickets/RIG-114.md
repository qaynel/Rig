# RIG-114 — Replace fixed npm-script discovery with whole-repo semantic discovery

**Status: COMMITTED (2026-08-24) — landed on this branch.**
Ticket: RIG-114 on [[Tickets]].

## Problem
Check discovery is a prototype across `catalog.js`, `plan.js`, `apply.js`,
`checks.js`, `ci-adapters.js` that recognizes only fixed npm script names. The
production contract (`GA-20`/`GA-21`) requires whole-repository, open-ecosystem,
polyglot semantic discovery — manifests, tool config, declared tasks — not a
fixed script-name list.

## Findings
The lint-format-roadmap "Check discovery/binding" row confirms: prototype
implemented, recognizes only fixed npm scripts, "not sufficient." `GA-20` sets
the whole repository as the discovery boundary; `GA-21` requires semantic command
discovery; components respect their own ignore rules and working directory.

## Solution (discovery engine)
1. **Component graph.** Walk the repo for component manifests (`package.json`,
   `pyproject.toml`/`setup.cfg`, `Cargo.toml`, `go.mod`, `Gemfile`, etc.) across
   root, workspaces, and nested/polyglot packages; each component records its
   working directory and ignore rules.
2. **Capability extraction, semantic not name-matched.** From each component
   derive lint/format capability from: declared tasks/scripts, tool config
   presence (`.eslintrc*`, `ruff.toml`, `.prettierrc`, `rustfmt.toml`…), and
   known tool binaries — mapping to a canonical `{lint, format}` capability with
   the exact command + cwd, regardless of the script's *name*.
3. **Ambiguity + gaps.** When a component exposes multiple plausible bindings,
   require a user choice (no silent pick). Components with no discoverable,
   runnable capability are named as **unprotected exclusions** and **suppress any
   whole-repository support claim** (per the partial-coverage contract).
4. **Wire into the pipeline.** `catalog.js`/`plan.js` consume the component graph;
   `apply.js` writes per-component bindings in `.rig/service-bindings.json`
   (argv-only, `shell:false`); `checks.js`/`ci-adapters.js` run per component in
   its cwd honoring its ignores.

## Acceptance mapping
- Cross-root/workspace/nested/polyglot discovery honoring ignore + cwd → steps 1–2.
- Ambiguous bindings require a choice; unbuildable components named + support
  claim suppressed → step 3.

## Implementation evidence (2026-08-24)
- Repository discovery now uses Git's complete visible-file set when available,
  with an unbounded filesystem fallback, and excludes Rig's own payload plus
  dependency metadata trees.
- Package scripts and Make/Just tasks are classified from task names and bodies;
  configured Ruff, Prettier, ESLint, Biome, dprint, Cargo, Go, RuboCop, and
  open-ended `role` + JSON-argv declarations feed one per-component binding.
- Every binding records source digests, exact argv, cwd, and inherited ignore
  files. Source drift fails closed before apply.
- Multiple plausible required-role commands produce `needs_user_choice` and
  block apply. Missing required roles name the component as an unprotected
  exclusion and set the whole-repository support claim to `suppressed`.
- New semantic regressions and the existing installed lint-format suite pass
  10/10. The relevant frozen cases pass, the complete signed 68-case oracle
  verifies, and a fresh four-axis review found no ticket-scope blockers. The
  final full gate passes 425 root, 15 pi-extension, and 6 rig-mcp tests.
