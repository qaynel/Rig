# RIG-104 — Unify the legacy `renderers.js` MCP path with the catalogue materializer

**Status: DESIGNED — implementation-ready (single source of truth + merge contract).**
Ticket: RIG-104 on [[Tickets]].

## Problem
`host-coverage-spec §3.2` records that the legacy Basic `renderers.js`/`HOST_FILES`
path and the à-la-carte catalogue MCP materialization were "deliberately left
untouched and deferred," which it calls incompatible with AT-HOST-5. Two
independent code paths can emit MCP config with divergent per-host key/shapes and
no single safe merge/preflight contract.

## Findings
- `renderers.js` hardcodes per-host key/shape inline: copilot `servers`, opencode
  `mcp`+`type`, codex TOML `[mcp_servers]`, else `mcpServers` — each embedded in
  a separate `renderX` function, plus a Tier A/B/C map and a `CREDENTIAL_SAFETY`
  map.
- §3.2 already researched the canonical data: `mcp` disposition
  (`repo`/`user_global`/`unsupported`), `surfaces.mcp` path, and
  `surfaces.mcp_key` overrides. That is the source of truth the code should read
  instead of re-encoding it twice.

## Solution (one disposition, both paths)
1. **Extract a single `mcp-hosts.js` table**: `{ host: { disposition, file,
   key, shape } }` populated from §3.2. Both `renderers.js` and the catalogue
   materializer import it; delete the inline per-host branches.
2. **One merge writer.** A single `mergeMcpEntry(existingObj, host, server,
   variant)` that: places the entry at the host's `key`, is idempotent
   (re-apply = no-op), and preserves every unrelated server for each shape
   (`mcpServers` object, copilot `servers`+`inputs`, opencode `mcp`, codex TOML
   block). This replaces the divergent `jsonFile`/`appendTomlBlock` call sites.
3. **Preflight = disposition gate.** `unsupported` → emit nothing, preserve +
   advise ([[RIG-103]]); `user_global` → advisory note only unless the
   user-global writer contract ([[RIG-111]]) applies; `repo` → merge.
4. **Policy parity.** Route network-capable MCP entries through the same active
   `.rig/network-policy.json` check as shell/web (MCP is never an enforcement
   bypass) with a test — mirrors §4 "one policy across network surfaces."

## Acceptance mapping
- One governing disposition + key map drives both install paths → step 1.
- Idempotent merge preserving unrelated servers for every shape → step 2 + a
  per-shape merge test.
- Network MCP obeys active policy, with a test → step 4.
- AT-HOST-5 coverage → shared with [[RIG-103]].
