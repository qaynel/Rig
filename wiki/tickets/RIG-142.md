# RIG-142 — spawnTask safety defaults caller-overridable; no guard or test

**Class: CORRECTNESS / SHELL TRUST.**
**Status: OPEN (2026-08-27) — GitHub #97.**
Ticket: RIG-142 on [[Tickets]].

## Problem

`spawnTask` sets two safety properties intended to enforce isolation:

```js
function spawnTask(argv, options) {
  return spawnGuardedSync(argv[0], argv.slice(1), {
    encoding: 'utf8',
    shell: false,
    env: isolatedTaskEnv(),
    ...options,       // spread last — caller wins
  });
}
```

Because `...options` spreads **last**, any caller can pass `shell: true` or a
replacement `env` and silently override both properties. No runtime assertion,
no type guard, and no test prevents or detects this. The isolation the rest of
AT-LF-21/AT-LF-22 relies on is structurally unguaranteed.

**What this means:** a future call site passing `{ shell: true }` defeats
shell-injection protection; one passing `{ env: process.env }` defeats
environment isolation — both silently, with no warning and no test failure.

## Location

`rig/lib/lint-format.js` — `spawnTask`, lines 507–514. The spread position is
the defect; the defaults themselves are correct.

## Required fix shape

Safety properties must be structurally enforced — placed **after** the spread
so they cannot be overridden, or validated against caller options and rejected:

- `shell` locked to `false` regardless of caller options.
- `env` not replaceable by callers; additional env vars go through an explicit,
  reviewed merge path, not a plain override.

A test must verify each property holds even if a caller attempts to override it.

## Acceptance

- Passing `shell: true` in options to `spawnTask` has no effect; the process
  still spawns without a shell (shell injection in argv has no effect).
- Passing `env: process.env` in options does not expose unrestricted env to the
  child; a secret key absent from `TASK_ENV_ALLOWLIST` is not visible.
- Named tests covering both invariants are in `tests/advanced-oracle.test.js`:
  `RIG-142 spawnTask shell is false even when caller passes shell: true` and
  `RIG-142 spawnTask env isolation holds even when caller passes env: process.env`.
- `spawnTask` must be added to `module.exports` in `rig/lib/lint-format.js` on
  the implementation branch to enable direct testing (confirmed by owner 2026-08-27).
- No existing test is broken by the fix.

Tests are implemented (2026-08-27). They are RED on both this branch (function
not exported) and on `rig-115-task-isolation` (safety defaults overridable).
They will be GREEN after `spawnTask` is exported and the spread order is fixed.
