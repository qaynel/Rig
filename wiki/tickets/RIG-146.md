# RIG-146 — Frozen AT-LF-20 proves one-use only via the in-memory flag, never the durable on-disk record

**Class: TEST QUALITY / SHELL TRUST (frozen oracle under-specifies).**
**Status: OPEN (2026-08-29) — GitHub #109 — accepted follow-up from the passing v5.0.0 review; non-blocking. Needs an owner re-sign to fix.**
Ticket: RIG-146 on [[Tickets]].

## Problem

[[RIG-138]] landed the durable one-use mechanism: `consumePlanApproval`
(`rig/lib/lint-format.js:443-453`) records execution on disk keyed by
`plan_digest` with an exclusive (`wx`) create, checked at `:483` before the
in-memory `approval.used` flag is set at `:486`.

The frozen acceptance test for the guarantee — `AT-LF-20`
(`tests/advanced-oracle.test.js:916-927`) — does not exercise that mechanism.
It reuses **one** `approval` object across both `executePlan` calls, so the
first call sets `approval.used = true` and the second is rejected at `:459`
(`if (approval.used) return { status: 'not_authorized' }`) **before** the
on-disk check at `:483` is ever reached. `AT-LF-20` would still pass with the
entire durable block (`:462-485`) deleted.

The real cross-process case — plan and execute in two different agent turns /
processes, where the JS object flag is gone — is covered only by `AT-PROC-1a`
in `tests/guarantee-coverage.test.js`, which is **not** in
`wiki/gate1/testing-infrastructure.manifest`. So the guarantee the owner
signed is pinned to its weak form; its real form rides a non-frozen test.

Behaviour is correct. This is a frozen-oracle coverage gap, not a defect.

## Location

- `tests/advanced-oracle.test.js` `AT-LF-20` (`:916-927`) — reuses the
  approval object.
- `rig/lib/lint-format.js` `executePlan` (`:455-488`) — in-memory check at
  `:459`, durable check at `:483`, flag set at `:486`.
- `tests/guarantee-coverage.test.js` `AT-PROC-1a` — the non-frozen test that
  already covers the cross-object case correctly.

## Required fix shape

- Rewrite `AT-LF-20` to pass a **freshly constructed** `{ plan_digest }`
  object (no `used` field) to the second `executePlan` call, so the on-disk
  record is the only thing that can reject it — matching `AT-PROC-1a`'s
  structure.
- Optionally also assert the record file exists under
  `.rig/lint-format/executions/` after the first call.
- `tests/advanced-oracle.test.js` is byte-pinned in
  `wiki/gate1/testing-infrastructure.manifest` (`7efc231c…`), so this edit
  **invalidates `gate1.sig` and needs a key-holder re-sign.** Batch it with
  any other pending oracle re-sign ([[RIG-133]], [[RIG-136]]).

## Acceptance

- `AT-LF-20` fails if the durable `consumePlanApproval` / on-disk record
  block is removed from `executePlan` (it currently passes).
- The second `executePlan` in `AT-LF-20` is rejected with the durable record
  present and no `approval.used` flag set on the object it receives.
- Manifest digest for `tests/advanced-oracle.test.js` updated and
  `gate1.sig` re-signed; `node scripts/check-advanced-spec.js` verifies.
- `AT-PROC-1a` continues to pass unchanged.
