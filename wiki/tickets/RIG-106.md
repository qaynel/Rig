# RIG-106 — Propagate Rig mode to subagents on every host that supports them

**Status: DESIGNED — needs a host-capability disposition, then a small wiring.**
Ticket: RIG-106 on [[Tickets]].

## Problem
`hooks/claude-codex-hooks.json` wires `rig-subagent.js` on `SubagentStart`, but
`hooks/copilot-hooks.json` has no subagent hook. On any subagent-capable host,
spawned subagents don't inherit Rig mode, so the ruleset silently drops inside
sub-tasks.

## Findings
- Claude/Codex hook schema uses capitalized lifecycle events and already has a
  `SubagentStart` entry running `rig-subagent.js` (issue #252). `rig-subagent.js`
  reads the active mode and injects `getRigInstructions(mode)` — reusable as-is.
- Copilot's hook schema (`copilot-hooks.json`) uses lowercase events and today
  declares only `sessionStart` and `userPromptSubmitted`. **Whether Copilot
  exposes a subagent lifecycle event at all is unverified** — inventing a
  `subagentStart` key that the vendor doesn't fire would be dead config and
  violates §4 "no speculative config."

## Solution (evidence-first, two steps)
1. **Disposition per host** (the real work): for each supported host, record in
   `host-coverage-spec` whether it has a subagent lifecycle event, with a vendor
   citation + date. Hosts with no subagent concept are marked **N/A**
   (acceptance bullet 2).
2. **Wire the ones that do.** For each host with a confirmed subagent event, add
   a hook entry invoking `rig-subagent.js` (the logic is host-agnostic) and a
   test asserting the active mode is injected into the subagent — mirroring the
   existing Claude/Codex `SubagentStart` test. If Copilot is confirmed to have
   one, add the lowercase-event entry to `copilot-hooks.json`.

## Why not just add a Copilot entry now
Because the ticket's own acceptance is conditional ("for each host **with** a
subagent lifecycle event"). The correct deliverable is the verified
per-host disposition; blind-adding an unfired event would pass no test and
mislead. This is the same evidence bar as [[RIG-110]].
