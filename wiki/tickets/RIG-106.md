# RIG-106 — Propagate Rig mode to subagents on every host that supports them

**Status: RESOLVED (2026-08-24) — disposition researched, Copilot wired, tests green.**
Ticket: RIG-106 on [[Tickets]].

## Problem
`hooks/claude-codex-hooks.json` wires `rig-subagent.js` on `SubagentStart`, but
`hooks/copilot-hooks.json` has no subagent hook. On any subagent-capable host,
spawned subagents don't inherit Rig mode, so the ruleset silently drops inside
sub-tasks.

## Findings
- Claude/Codex hook schema uses capitalized lifecycle events and already has a
  `SubagentStart` entry running `rig-subagent.js` (issue #252). `rig-subagent.js`
  reads the active mode and injects `getRigInstructions(mode)` — reusable as-is.
- Copilot's hook schema (`copilot-hooks.json`) uses lowercase events and today
  declares only `sessionStart` and `userPromptSubmitted`. **Whether Copilot
  exposes a subagent lifecycle event at all is unverified** — inventing a
  `subagentStart` key that the vendor doesn't fire would be dead config and
  violates §4 "no speculative config."

## Solution (evidence-first, two steps)
1. **Disposition per host** (the real work): for each supported host, record in
   `host-coverage-spec` whether it has a subagent lifecycle event, with a vendor
   citation + date. Hosts with no subagent concept are marked **N/A**
   (acceptance bullet 2).
2. **Wire the ones that do.** For each host with a confirmed subagent event, add
   a hook entry invoking `rig-subagent.js` (the logic is host-agnostic) and a
   test asserting the active mode is injected into the subagent — mirroring the
   existing Claude/Codex `SubagentStart` test. If Copilot is confirmed to have
   one, add the lowercase-event entry to `copilot-hooks.json`.

## Why not just add a Copilot entry now
Because the ticket's own acceptance is conditional ("for each host **with** a
subagent lifecycle event"). The correct deliverable is the verified
per-host disposition; blind-adding an unfired event would pass no test and
mislead. This is the same evidence bar as [[RIG-110]].

## Resolution (2026-08-24)

Researched all 19 `SUPPORTED_HOSTS` against vendor documentation for a
subagent lifecycle hook that can *inject* context (not merely observe or gate
subagent creation — loading Rig mode needs injection). Full findings +
citations: [reasoning trace](../reasoning/2026-08-24-subagent-mode-propagation-disposition.md),
recorded in [host-coverage-spec §3.1a](../specs/host-coverage-spec.md#31a-subagent-lifecycle-event-disposition-rig-106).

- **Copilot / Copilot CLI is wired** (the ticket's named gap): GitHub's
  `subagentStart` event fires for both surfaces and takes the same top-level
  `{ additionalContext }` shape as `sessionStart`. `hooks/copilot-hooks.json`
  gained a `subagentStart` entry invoking `hooks/rig-subagent.js`;
  `hooks/rig-runtime.js`'s `writeHookOutput` Copilot branch previously
  injected only on `SessionStart` and silently dropped everything else — it
  now also injects on `SubagentStart`. Verified by two new cases in
  `tests/hooks.test.js` (mode present -> `additionalContext` set with no
  Claude/Codex-shaped wrapper; mode absent -> silent). **Caveat confirmed by
  review:** `subagentStart` never fires for Copilot's built-in
  `general-purpose` agent (only named/custom agents emit it) — the wiring is
  correct as shipped, but a general-purpose Copilot subagent has no vendor
  hook to inherit Rig mode through, and nothing on Rig's side can change that.
- **Claude and Codex/vscode-codex** were already wired and unchanged.
- **Every other host is recorded N/A**, each for a distinct evidenced reason:
  cursor, codewhale, and **hermes** have a subagent hook that can only
  gate/observe, not inject (Hermes was corrected into this bucket from an
  initial "no mechanism" read — it has a real 26-event `~/.hermes/config.yaml`
  system, but `subagent_start`/`subagent_stop` are explicitly observer-only);
  gemini, antigravity, devin, and windsurf have hooks but no subagent-scoped
  event; opencode has an open, unshipped feature request for one; openclaw's
  only subagent event lives in its plugin-hooks catalog, not the operator
  `HOOK.md` mechanism Rig grafts; cline's subagent hooks are SDK-only
  (`@cline/agents`), not the repo `.cline/hooks/` surface Rig grafts; pi has no
  native hooks and its one documented extension (`@vahor/pi-hooks`) has no
  subagent event either; kiro's `AgentSpawn` was initially left unresolved but
  is now resolved N/A — its payload carries only `session_id` (no
  `agent_id`/`subagent_type`), reading as per-session, not per-subagent (a
  first-wire test is still the only way to be fully certain, given an open
  vendor bug report about its firing behavior); swival and generic have no
  hook mechanism at all.

Corrections applied 2026-08-24 after independent review against primary
sources: [reasoning trace](../reasoning/2026-08-24-subagent-disposition-corrections.md).

`npm test` is green (root 384/384, pi-extension 15/15, rig-mcp 6/6). Doesn't
touch the signed oracle.
