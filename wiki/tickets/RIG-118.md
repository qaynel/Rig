# RIG-118 — Make the full plugin distribution discoverable from the README

**Delivery state (RIG-118):** delivered
**Status: DONE (2026-08-26) — GitHub #60 closed.**
Ticket: RIG-118 on [[Tickets]].

## Problem
The richer plugin installs were claimed to be undocumented in the README.

## Findings (verified 2026-08-24)
The README already carried both the Tier 1 host-entrypoint matrix **and** an
"Install Full Plugin Distribution" table with per-host load/install commands
(Claude, Codex, OpenCode, pi, Gemini CLI, Copilot CLI, Swival, OpenClaw, Devin)
plus a Hermes section. So the ticket's core ("host matrix + install command in
README") was largely already met. Two gaps remained:
- No explicit **pointer-only vs full-hook** marking (acceptance bullet 2).
- No pointer to the standalone `rig-mcp/` server for prompt-menu-only hosts.

## Solution (landed)
Edited the README full-distribution table:
- Added a **Capability** column and a legend defining *full-hook* (host runs
  Rig's lifecycle hooks — real tool-boundary behavior) vs *pointer-only* (loads
  instructions only; workflow advisory). Marked each host accordingly and added
  the Hermes row into the table.
- Added a sentence directing prompt-menu-only hosts to the `rig-mcp/` server
  (`rig` prompt / `rig_instructions` tool), linking [[RIG-101]].

## Verification
Rendered table lists every shipped host with its capability class; the
portability doc link is retained. No code path affected; `npm test` green.

## Acceptance

- **Superseded for v6.0.0:** the README presents one install path, the agent-led
  onboarding step and the selected-service outcome, without a per-host support
  matrix (owner-locked product direction).
  → tests/standards-contracts.test.js::README documents the single 6.0.0 install command and agent-led onboarding without a host matrix
