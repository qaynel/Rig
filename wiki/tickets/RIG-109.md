# RIG-109 — Test the runtime through its shipping path, not by direct `require`

**Status: DESIGNED — blocked on [[RIG-107]] (needs the entrypoint first).**
Ticket: RIG-109 on [[Tickets]].

## Problem
The signed oracle binds behavior with `require(file)[name]`, so 68/68 green is
(per the testing-strategy topic) "behavior at a seam the product does not use."
Even correct modules aren't proven reachable.

## Findings
- The oracle's value is provenance/immutability, not reachability — it verifies
  the *function* behaves, not that any shipping flow calls it.
- There is currently no installed entrypoint to test through ([[RIG-107]]); once
  `.rig/bin/rig` exists, an end-to-end test can drive real behavior.

## Solution (complement, don't replace, the oracle)
1. After [[RIG-107]] lands `.rig/bin/rig`, add at least one **end-to-end** test:
   install `--with-runtime` into a temp repo, run `.rig/bin/rig inspect →
   recommend → plan → apply → check` for the lint-format leaf, and assert the
   observable result (bindings written, check runs read-only, exit codes). This
   asserts the *product* works, not just the seam.
2. Keep the direct-`require` oracle as the frozen contract; the e2e test is
   additive evidence. Document in `topics/testing-strategy.md` that the
   "green oracle is not evidence the product works" caveat is now closed by the
   e2e coverage, and link the test.
3. Fold in the [[RIG-108]] `release-evidence.js`-through-`review-receipt.js` test
   as a second shipping-path example.

## Dependency
Cannot land before [[RIG-107]]. This ticket is the acceptance closure for the
testing-strategy caveat and should ship in the same PR as the entrypoint.
