## Problem

`rig/lib/host-capabilities.js` pins one official-doc citation per host and the
product treats "supported / unsupported" as evidence-gated. The intent owner
wants every deliverability gap backed by an official citation that actually
substantiates the claim. During review the citations were spot-checked against
vendor docs: most hold, but the audit surfaced one false claim, several
citations that don't match the assertion they sit next to, and — structurally —
no check ties a citation to the specific claim it is supposed to prove, so this
class regenerates. One clubbed ticket, not one per host.

## Structural sub-note (feeds [[RIG-125]])

The audit only found 129.1 because a human read the cited page. Nothing in the
gate checks that a citation URL substantiates the specific axis claim, so
"supported/unsupported" assertions can drift from their evidence indefinitely —
each future review re-discovers the drift. Consider a lightweight discipline:
each `evidence.citation` names the exact claim it proves (path/key/scope), and a
review step (or the authored-service gate) flags any host whose citation is a
bare landing page.

## Provenance belongs in the model, not in prose (added 2026-08-25)

A claim about another vendor's tool has exactly three legitimate states —
`verified`, `unsupported`, `unknown` — and *"the spec says so because an agent
once inferred it"* is not one of them.

Carry the state and its evidence in the host model rather than in prose:

```yaml
cursor:
  rules:
    path: ".cursor/rules"
    status: verified
    evidence:
      type: first-wire
      receipt: receipts/cursor/rules-2026-08.json
```

Then let generation decide what the docs are permitted to say: `verified` may
render "supported"; `unknown` may only render "unverified"; `unsupported` may
only render "not supported". This makes **undocumented certainty about
third-party behaviour unrepresentable in generated output**, instead of
something a reviewer has to catch in prose after the fact — the same move as the
rest of the programme, and the reason it is stronger than "run the wire, or
downgrade the claim by hand."

This class is also the one review cannot close under any budget: no amount of
reading this repository establishes what another vendor's tool reads off disk.
19 hosts × 5 axes is finite and linear — run the wires, or mark them `unknown`.
