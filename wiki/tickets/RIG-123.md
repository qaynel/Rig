# RIG-123 - Implement the OpenClaw global MCP opt-in

**Status: COMMITTED (2026-08-24) — landed on this branch.**
Ticket: RIG-123 on [[Tickets]].

## Problem

OpenClaw exposes one user-global JSON5 MCP registry. Rig had a working
`rig-mcp` server but no explicit installation path that warned about the
all-workspaces effect, installed the locked runtime, attributed the entry, or
removed it safely.

## Resolution

- `install.sh` and `rig/bootstrap.sh` accept `--openclaw-mcp`; the default path
  does not invoke OpenClaw or npm, while the selected path warns before target
  writes and preflights `openclaw`, `node`, and `npm`.
- The shared OpenClaw helper copies `rig-mcp/` into
  `.rig/runtime/rig-mcp`, runs `npm ci --omit=dev --ignore-scripts`, and calls
  only `openclaw mcp set` with a `node` stdio server definition.
- A clone-local install ID produces the `rig-<install-id>` key. The ledger
  records the global file, server key, install identity, runtime, and pending /
  applied state; a successful native registry read precedes any dependency
  install or global write, a recorded key is replaced on reinstall, and an
  attributed key from another install is refused.
- Uninstall calls `openclaw mcp unset` before removing the runtime. A missing
  or failing CLI leaves the runtime and ledger entry in place, reports
  best-effort, and preserves unrelated OpenClaw servers. If `mcp set` changes
  configuration before failing, Rig immediately attempts native rollback; a
  failed rollback remains pending so uninstall retries it before teardown.
- Reinstall and uninstall first compare the native server value with the local
  ledger value. A later user replacement is neither overwritten nor deleted;
  a failed reinstall restores the previous Rig value only after that exact
  ownership check. The warning names the same configured path that the native
  OpenClaw process receives.
- `rig-mcp/package-lock.json` is committed for deterministic runtime setup.
