## Problem

Substantial-but-routine tasks exhaust the 5h/weekly account limit. Three pasted
session transcripts (`.context/attachments/`, see
[[2026-08-25-token-burn-investigation]]) show the cost is **tool-call volume and
nested model spawns, not context-window pressure** — no session hit a context
wall; they hit the account rate limit. Three multipliers, ranked:

1. **Nested reviewer retry loop.** `scripts/review-receipt.js` (`spawnSync`,
   30-min timeout, `review-receipt.js:18-22`) launches a *second full model* to
   review the whole diff. When it returned `verdict: fail`, the agent fixed the
   finding and re-ran the review — **three full nested-review cycles in one turn**
   (528fiH lines 262, 646, 840), each interleaved with a full gate run.
2. **Full-gate `npm test` as the inner loop** — 6–7 runs per session (the entire
   CI gate incl. the `.venv`/pandas benchmark), used as the red/green step, while
   the documented fast subset `npm run test:rig` sat unused.
3. **Per-turn instruction tax.** CLAUDE.md tells every agent — even for a one-line
   ask — to re-read `routing.md`, read the wiki, read each chosen skill *in full*,
   and rewrite the wiki every 3 minutes. Correct for long work; a flat tax on small
   work, and it compounds on every resume.

## Proposed resolution

Three independent changes; can land separately.

1. **Cap the nested reviewer.** A `fail` verdict is real signal — stop and surface
   it, never silently re-review. Limit re-reviews to **one**. Use a cheap model
   (Haiku/Sonnet) for interim passes and reserve the expensive model for the final
   receipt. It is a **release-only** gate — never run mid-development. Enforce the
   cap where possible (a guard/env in `review-receipt.js` or the release skill)
   rather than relying on agent discipline alone.
2. **Inner-loop test discipline.** During red/green, run `npm run test:rig` or the
   single relevant test file. Full `npm test` runs **once**, right before push.
   Encode this in the implementation/tdd guidance so agents stop using the full
   gate as the inner loop.
3. **Scope the per-turn tax.** Make "read the full skill / update wiki every 3 min
   / re-read routing" apply to **multi-step** work, not every small ask. Adjust
   CLAUDE.md and `routing.md` so a single-file/one-liner has a lighter path.

## Design note / oracle intersection

Change 1 touches the release-review contract (AT-GATE-3 "fresh reviewer session").
The *fresh-session* requirement stays; only the auto-retry and interim-model choice
change. **Resolved: no re-sign needed** — neither `scripts/review-receipt.js`
nor `rig/lib/release-evidence.js` is in `wiki/gate1/testing-infrastructure.manifest`,
and the frozen `AT-GATE-3` test only exercises `validateReviewReceipt`'s
fresh-session/report-only/digest contract, not the wrapper's CLI or retry
count. Verified the frozen test still passes unmodified. Changes 2 and 3 are
instruction/policy only, as expected.

## Acceptance (implemented 2026-08-25)

- A failing release review stops and reports; the agent performs at most one
  re-review after a fix, and this is enforced, not merely instructed.
- Interim review passes may use a cheap model; the final receipt uses the
  designated release model. The receipt is never generated mid-development.
- Implementation/TDD guidance directs the inner loop to `npm run test:rig` or a
  single test file, with the full gate run once before push.
- CLAUDE.md/routing distinguish a lightweight path for single-step tasks from the
  full read-routing/read-wiki/update-every-3-min cadence for multi-step work.
