# RIG-152 — "In this source checkout" conditionals in routing.md are always-false once installed

**Class: POLISH, pure-markdown.**
**Status: DONE (2026-08-31) — GitHub #129 — found during Path A install-bug investigation.**
Ticket: RIG-152 on [[Tickets]].

## Problem

`rig/tier-1/routing.md:5-8`:

> Apply `.rig/rules/rig.md` to every coding task and
> `.rig/rules/communication.md` to every message you send the user, then
> choose the smallest set of skills whose trigger matches the work. In this
> source checkout, use `rig/tier-1/rules/rig.md` and
> `rig/tier-1/rules/communication.md` instead.

Same pattern at `routing.md:29-31` for skill paths. The copy op that
installs this file (`copyOp`, `manifest.json:4`) does no templating —
verified by diffing an installed copy against source: byte-identical. So
every installed `.rig/routing.md`, in every target repo, carries the
literal clause "In this source checkout, use `rig/tier-1/...` instead" — a
branch that is **never true post-install**, not just situationally
irrelevant: an installed copy is by definition not "this source checkout"
(that phrase only resolves inside the Rig monorepo itself). This is
distinct from — and lower-severity than — [[RIG-150]], which is about a
path this same pattern-family *should* have used but didn't; this ticket
is about dead prose that already uses the pattern but ships to readers for
whom it can never apply.

What a stranger repo's agent does on hitting this: most capable agents
recognize `rig/tier-1/...` doesn't exist in their tree and silently fall
through to the `.rig/...` branch, losing a beat to confusion. A
literal-instruction-following instruction-only host has no such fallback
reasoning available and just carries the dead prose forward as context.

## Location

`rig/tier-1/routing.md:5-8`, `:29-31`.

## Required fix shape

Split the file's copy at install time so the "in this source checkout"
alternative is dropped from what actually ships to a target repo — either
a small template/transform in the copy op (`payload.js` already has a
transform hook used for skill frontmatter rewriting,
`installVendoredSkillsOp`, that could be extended to `routing.md`'s copy
op), or maintain two variants (dev-checkout doc vs. installed doc) and copy
the installed one. Prefer the transform: one source of truth, rendered two
ways, rather than two hand-synced files.

**Direction agreed 2026-08-31 (option B) — supersedes the "prefer the
transform" line above.** No `payload.js` transform and no two-file split.
The "In this source checkout" conditionals are rewritten as explicit
instructions to the onboarding host agent (reconcile these paths against
what actually got installed). Markdown-only. Rationale: the adaptation
belongs to the host agent at install time, not to installer code — that is
the forward-deployed model ([[what-rig-is]], `GA-36`). This drops acceptance
bullet 3's "diff installed copy against source" regression test in favour of
a check that the reframed prose names no unresolvable path. Bundled with
[[RIG-151]] and [[RIG-124.2]], one signature.
[[reasoning/2026-08-31-routing-md-adaptation-not-transform]]

**Design filed 2026-08-31** — [[reasoning/2026-08-31-routing-hygiene-design]].
Both "In this source checkout, use X instead" clauses (header paragraph, skill-
path paragraph) become parenthetical asides scoped "Working in the Rig source
repo…"; the `rig/tier-1/...` paths are retained inside them, so contributor
guidance survives and the never-true conditional is gone. **Owner approved the
wording 2026-08-31** — oracle frozen, `rig-tdd` may proceed.

## Acceptance

- An installed `.rig/routing.md` contains no "In this source checkout" conditional
  and no bare `rig/tier-1/…` paths outside a contributor-scoped parenthetical; the
  Rig-source dev-checkout copy retains the paths for contributor use.
  → tests/installed-router-hygiene.test.js::RIG-152 — router hands the onboarding agent no never-true "source checkout" conditional

## Evidence

Direct diff, 2026-08-30: installed `.rig/routing.md` (via `sh
rig/bootstrap.sh --hosts claude --target <tmp>`) is byte-identical to
`rig/tier-1/routing.md` — `diff` exits 0. Confirmed `rig/` does not exist
in the installed target (`ls "$TMPD/rig"` → no such directory), so the
named alternative path is unreachable by construction. Full trace:
[[reasoning/2026-08-30-path-a-bug-investigation]] §2.
