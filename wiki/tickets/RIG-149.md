# RIG-149 — Vendored `rig` switchboard installs as `rig-rig`, breaking routing.md's own fallback instruction

**Delivery state (RIG-149):** delivered
**Class: CORRECTNESS, installer-code.**
**Status: DONE (2026-08-30; board corrected 2026-10-13) — GitHub #126 (closed as COMPLETED, PR #132) — found during Path A install-bug investigation.**
Ticket: RIG-149 on [[Tickets]].

## Problem

`rig/tier-1/routing.md:100-102` ("Fallback to the router"):

> If a request does not match any Tier 1 skill above and the user has not
> named a specific vendored skill, invoke the vendored `rig` router (the
> `/rig` switchboard shipped from the swallowed suite)...

The skill this names is `rig/catalog/skills/_core`, whose `SKILL.md`
frontmatter declares `name: rig` (`_core/SKILL.md:2`). `_core` is not in
`rig/lib/skills.js`'s `RESERVED` set, so it installs like any other
vendored skill. For Claude/Codex/Antigravity hosts,
`installVendoredSkillsOp` applies `rewrite_name_prefix: "rig-"` uniformly
(`manifest.json:45-46`; `finalName = ${prefix}${skill.name}`,
`payload.js:94`) — so the skill declaring `name: rig` becomes `rig-rig`,
installed at `.claude/skills/rig-rig/SKILL.md` with its own frontmatter
`name:` line rewritten to `rig-rig` too.

Reproduced directly: `sh rig/bootstrap.sh --hosts claude --target <tmp>`
then `cat .claude/skills/rig-rig/SKILL.md` → `name: rig-rig`. There is no
installed skill addressable as plain `rig` for a native-dispatch host.
`routing.md`'s own fallback names a skill that doesn't exist under that
name for the hosts most likely to use native by-name skill dispatch in the
first place. The same collision produces `rig-rig-upgrade` for the
vendored `rig-upgrade` skill — ugly but still unique, since only `_core`'s
declared name exactly equals the prefix.

The `.rig/skills/rig/SKILL.md` copy (from the `host: "neutral"` entry,
`manifest.json:44`, no prefix) does carry the correct unprefixed name — but
that's the instruction-only fallback location; Claude's native skill
discovery reads `.claude/skills/`, not `.rig/skills/`.

## Location

- `rig/lib/payload.js:91-113` (`installVendoredSkillsOp`), specifically
  `:94` (`finalName = ${prefix}${skill.name}`).
- `rig/catalog/skills/_core/SKILL.md:2` (`name: rig`).
- `rig/manifest.json:44-46` (three `install_vendored_skills` entries; only
  the `claude` and `codex`/`antigravity` entries carry
  `rewrite_name_prefix`).
- `rig/tier-1/routing.md:100-102` (the instruction naming "the vendored
  `rig` router").

## Required fix shape

Either:
- Exempt `_core` from the generic prefix rule so it installs at
  `.claude/skills/rig` (unprefixed) for native hosts, matching its
  unprefixed neutral-path install — the fix is local to
  `installVendoredSkillsOp`'s filter/naming logic, one special case; or
- Update `routing.md:100-102` to name the skill by its actual installed
  name, `rig-rig`, for native hosts.

Recommend the first: a skill named exactly `rig` is clearly meant to be
the top-level entrypoint, and doubling its own name on install is an
unintended side effect of a blanket rule, not a deliberate choice.
