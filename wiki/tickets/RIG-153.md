# RIG-153 — No frozen instrument exists to measure adaptation quality

**Class: PROCESS / TOOLING GAP (no code yet).**
**Status: OPEN (2026-08-30) — GitHub #130 — found during Path A install-bug investigation.**
Ticket: RIG-153 on [[Tickets]].

## Problem

The only adaptation-quality measurement on record is
[[reasoning/2026-08-30-adaptation-eval-claude-task-master]]: one holistic
Sonnet pass, self-reported ±5, scoring +12/100 — and it scored a
`--with-runtime` install, not the default product
([[reasoning/2026-08-30-office-hours-path-a-path-b-scoping]] already
corrected this framing; confirmed again independently in
[[reasoning/2026-08-30-path-a-bug-investigation]] §0). No rubric file,
fixed axis list, weight scheme, pinned model, or clean-checkout procedure
exists anywhere in the repo. Path A's own stated goal — "fix the concrete
install bugs and freeze a real measurement instrument, then re-baseline" —
cannot produce a comparable number without one.

## Required instrument shape

- **Fixed axes with weights**, drawn from the existing eval's own
  dimensions (they already proved discriminating): config preserved (no
  clobber/data loss — weighted highest, it's correctness not taste),
  breakage/dangling-reference count (exactly what [[RIG-149]]/[[RIG-150]]/
  [[RIG-151]]/[[RIG-152]] are instances of — mechanically detectable
  without a model call), signal-vs-noise (relevant-skill count and byte
  weight against total installed), net capability added, reversibility
  (uninstall round-trip). Breakage-count and config-preservation weighted
  above taste-driven axes.
- **A pinned model and fixed prompt template** (or documented sampling
  temperature) so repeat runs are comparable.
- **A clean-checkout procedure**: fresh clone/copy of the target repo, one
  documented `bootstrap.sh` invocation logged alongside the score,
  `git status`/`git diff` captured as raw evidence — the existing eval
  already does this part; codify it as a required step, not an incidental
  choice.
- **Running the default install, not `--with-runtime`** — matching what a
  real user gets. A `--with-runtime` run needs its own separately labeled
  rubric pass if it's ever evaluated.

The breakage-count axis can be partly mechanical immediately: a pre-eval
lint pass that greps/tree-diffs for the exact defect shapes [[RIG-149]]
through [[RIG-152]] catch could regression-test this axis before any
model call, and before the next eval run.

No score is proposed here; this ticket specs the instrument, not a
re-score.

## Acceptance

**Instrument (option A — this pass):**

1. `tests/installed-router-hygiene.test.js` is extended with test blocks
   covering all six RIG-148→152 defect shapes: bare `(RIG-NNN)` citations,
   `wiki/status.md` 3-minute cadence, never-true "source checkout" conditional,
   dangling `.rig/skills/implementation/SKILL.md` path, `rig`→`rig-rig` name
   collision, and missing `ensure_gitignore_block` for Rig-owned install paths.
   All six tests pass green in `npm test`.

2. `wiki/specs/adaptation-measurement-rubric.md` exists and contains: 2 hard
   gates (G1 Config Preserved, G2 Zero Breakages — each MET/UNMET with
   justification; gate violation = GATE-FAILED), 3 graded axes (A1
   Signal-vs-Noise, A2 Net Capability Added, A3 Reversibility — each
   fail/partial/pass, equal weight, no weight vector), per-axis profile output
   format (not a scalar), the low-confidence-aggregate caveat, the
   clean-checkout procedure, the prompt template, and the model-EOL re-pin step.

3. The rubric names a dated snapshot of `claude-sonnet-5` (recorded verbatim
   from `claude --version` or API response — never a floating alias) as the
   pinned judge model; mandates ≥3 runs; requires mean and observed spread per
   axis; does not accept self-reported model confidence as a substitute for
   observed spread.

4. The rubric anchors on eyaltoledano/claude-task-master
   (`inspo/claude-task-master-main/`) as the baseline target and records both
   the Rig branch SHA (`38493a9bf3...`, `qa-prod-v5`) and the target's commit
   SHA for each run.
