# RIG-117 — Fix stale plugin/repo identity across manifests and README

**Status: RESOLVED (landed, `npm test` green).**
Ticket: RIG-117 on [[Tickets]].

## Problem
Published plugin metadata pointed at the dead repo
`github.com/vaibhav-kodiyan/agentic-harness-demo`. The real remote is
`github.com/qaynel/Rig-v0.1`, so every customer's "view source / report issue"
link went to the wrong place.

## Findings (verified 2026-08-24)
The stale slug lived in: `.codex-plugin/plugin.json` (×3 incl. `websiteURL`),
`.devin-plugin/plugin.json` (×2), `.github/plugin/plugin.json` (×2),
`antigravity-plugin/plugin.json` (×2), `.agents/plugins/marketplace.json`,
all six `.openclaw/skills/*/SKILL.md`, `skills/rig-help/SKILL.md`,
`.opencode/plugins/rig.mjs`, and the generator `scripts/build-openclaw-skills.js`.
`.claude-plugin/plugin.json` carried only the author profile URL (fine).
`install.sh` and README already use `qaynel/Rig`.

## Solution (landed)
1. Replaced every `vaibhav-kodiyan/agentic-harness-demo` occurrence with
   `qaynel/Rig-v0.1` across the manifests, marketplace entry, openclaw skills,
   the opencode plugin, and the openclaw generator (so a regen won't reintroduce
   it).
2. Extended `scripts/check-versions.js` with an **identity guard**: it fails
   closed if the slug `agentic-harness-demo` survives in any shipped manifest
   (`.claude-plugin`, `.codex-plugin`, `.devin-plugin`, `.github/plugin`,
   `antigravity-plugin`, `gemini-extension.json`, `.agents/plugins/marketplace.json`).
   Output now reads `... identity URLs clean across 7 manifests.`
3. Corrected the two wiki references (`product-spec.md` R3 gap row + the
   `RIG_REPO` stub default) as part of [[RIG-121]].

## Open owner decision (flagged, not taken)
`install.sh` (`REPO="${RIG_REPO:-qaynel/Rig}"`) and the README install commands
use `qaynel/Rig`, but the actual remote is `qaynel/Rig-v0.1`. The manifests now
match the remote. Before v5.0.0 publish, reconcile the two: either rename the
GitHub repo to `Rig`, or change `install.sh`/README to `qaynel/Rig-v0.1`.
Recommendation: publish/alias as `qaynel/Rig` (cleaner user-facing install), and
point the manifests there once that repo name exists. This is a naming call for
the owner — see [[RIG-120]] release ceremony.
