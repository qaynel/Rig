## OpenClaw follow-up
The global OpenClaw opt-in is deliberately held at the signed-oracle boundary.
It adds `--openclaw-mcp`, warns before writing the user's global context, uses
`openclaw mcp set` / `unset` rather than parsing JSON5, packages a locked
runtime, assigns each installation a distinct server name, and preserves the
runtime if OpenClaw cannot remove that server. The default install remains
unchanged. The executable acceptance test is red only because the option and
runtime packaging are not implemented yet; it is ready for the owner's Gate 1
signature.

## Problem
`rig-mcp/` is a working MCP server (serves the ruleset as the `rig` prompt and
the `rig_instructions` tool) but nothing references it: no host manifest
declares it, no installer launches it, no doc explains wiring. It is built but
unreachable.

## Findings
- `rig-mcp/index.js` connects `McpServer` over `StdioServerTransport`, registers
  the `rig` prompt and `rig_instructions` tool, both driven by the shared
  `buildInstructions()` (identical rules to hooks + pi extension). Modes served:
  `lite`, `full`, `ultra`.
- Distribution surface that could reference it: `docs/agent-portability.md`
  (adapter matrix), README (now has a pointer as of [[RIG-118]]), and the
  per-host MCP configs. `host-coverage-spec §3.2` already defines the MCP
  disposition per host — `rig-mcp` is the natural payload for the
  prompt-menu-only case the server's own header calls out (#70).

## Solution (bounded, three parts)
**1. Pick the first real host.** Use a `mcp: 'repo'` host from §3.2 whose primary
Rig injection is weakest — **gemini** or **opencode** are good first wires
(committable `mcpServers`/`mcp` file). Register `rig` there via that host's MCP
config, pointing `command: "node"`, `args: [".rig/runtime/rig-mcp/index.js"]`
(runtime install) — reuse the existing `renderers.js` shapes so credentials stay
env-ref only. This is the "at least one host lacking always-on injection
registers the server, verified by a test" acceptance.

**2. Document every host's wiring.** Add a `rig-mcp` section to
`docs/agent-portability.md` with copy-paste config per supported shape
(`mcpServers` / copilot `servers` / opencode `mcp`+`type` / codex TOML
`[mcp_servers]`), taken from the one source of truth [[RIG-104]] will establish.

**3. Regression.** In the rig-mcp suite (gated once [[RIG-102]] lands), spawn
`node rig-mcp/index.js` over stdio via `@modelcontextprotocol/sdk` client,
`initialize`, then assert `rig_instructions` returns non-empty text for each of
`lite`, `full`, `ultra`. This requires the SDK at test time (add it as a rig-mcp
devDependency or vendor a minimal stdio client).

**4. Record exclusions.** Hosts intentionally not served by `rig-mcp` (e.g. pi —
`mcp: 'unsupported'`, see [[RIG-103]]) are already recorded in
`host-coverage-spec`; add a one-line "rig-mcp: N/A" note per excluded host.

## Dependencies / sequencing
Best done with [[RIG-102]] (gate the suite) and [[RIG-104]] (single MCP
disposition source), and after [[RIG-107]] gives `rig-mcp` a runtime install
location. Standalone-doc portion can land immediately.
