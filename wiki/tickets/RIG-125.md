## Why this is the top ticket

The intent owner's stated fear is a circular SDLC: raise tickets → resolve →
re-review → the same class of issue resurfaces → more tickets, forever. This
branch already shows that loop **having happened**: three tickets are marked
Done/Committed on the board while their acceptance is **not** met in the shipped
code. The common root cause is structural, not incidental — the same fact is
defined in several places, and acceptance is proven by a narrow unit test that
checks the *mechanism* in one place instead of the *end-to-end property*. So
"Done" is declared, and the next fresh review re-discovers the gap.

Fixing the individual symptoms (RIG-126/127/128) without fixing this shape means
they come back. This ticket is the loop-breaker.

## The structural pattern

- **MCP disposition is defined ~3×:** `REGISTRY` (`host-capabilities.js`), the
  override tables in `mcp-hosts.js`, and `GLOBAL_MCP_CONTRACTS`
  (`global-writes.js`) — read by consumers that don't all read the same one.
- **Uninstall is defined 2×:** journal-based `lifecycle.js` and receipt-based
  `uninstall.js`, both reachable from `.rig/bin/rig`, disagreeing on what an
  install is.
- **Acceptance tests encode the mechanism, not the property:** unit tests assert
  one writer's output; nothing asserts "the two paths agree", "the printed flow
  runs", or "install fully reverses on uninstall".

This shape guarantees regression-by-review: every host or lifecycle change can
re-introduce a divergence that no test forbids, and the next reviewer finds it.

## Recommended direction (the loop-breaker)

Encode each cross-cutting property as one test, so "Done" becomes trustworthy:

1. **One MCP disposition authority + an equivalence test.** Collapse to a single
   derived table every consumer reads (renderers, catalogue descriptor,
   global-writes). Add a test asserting `{disposition, autoWrite, file, key}`
   agree across the renderer path and the emitted host-contract for **all 19
   hosts**. (Concrete divergences to fix live in RIG-128.)
2. **One uninstall authority.** Make the `--uninstall` flag delegate to the
   journal path (or remove it). (Concrete orphan defects live in RIG-127.)
3. **A real install→uninstall roundtrip test** and **a test that executes the
   printed bootstrap sequence to a green `check`.** These two are what would have
   caught RIG-104/105/107 before they were called Done.

Re-verify RIG-104, RIG-105, RIG-107 against the new property tests before they
stay in Done. This ticket blocks trusting the release ceremony (RIG-120).

## Root cause beneath the symptom (added 2026-08-25)

Full analysis: [[2026-08-25-structural-nondeterminism-root-cause]]. This ticket
names the symptom correctly — parallel sources of truth, acceptance that encodes
the mechanism. Two further facts decide whether fixing it actually ends the loop.

**1. The signed oracle is the wrong seam, and it is frozen at that seam.** All
**68** acceptance cases in `tests/advanced-oracle.test.js` load through
`api(file, name)` — `require(rig/lib/<file>)[<name>]`, one module, one exported
function. Only **5 of 65** oracle tests reach the shipping path. So the *signed*
definition of "acceptable" is "each function, called alone, behaves". Every
round-3 finding is a composition property, which that definition cannot express.
The file is byte-pinned under the owner key, so no agent can grow it — RIG-120
round 2 recorded exactly that refusal. `rig/lib/` grew across the branch; the
manifest was re-signed 3 times in 20 commits.

**Consequence for this ticket:** the four loop-breaker tests below must land
**inside the signed oracle**, under the re-sign ceremony [[RIG-120]] already
needs — not beside it in `release-blockers.test.js`. Put them beside it and the
signed definition of Done still describes the unit seam, and rung 4 of the ladder
below arrives on schedule. Cost is one ceremony, not two.

**2. Every previous fix for this loop was a new proxy, not the property.**

| Rung | Trap found | Fix shipped | Why the next round beat it |
|---|---|---|---|
| 1 | Suite asserts inventory (`TODO` counts as non-empty) | Assert behavior | Behavior asserted at a seam nothing reaches |
| 2 | Oracle green at a seam with zero production callers | `tests/runtime-caller-graph.test.js` — every `rig/lib` module must have a non-test importer | "Has a caller somewhere" ≠ "is on the path a user runs"; two callers may read two different tables |
| 3 | **now** — `mcp-hosts.js` has exactly one importer | — | — |

Rung 3 verified in code 2026-08-25:

```
$ grep -rn "mcp-hosts" rig scripts hooks tests | grep -v "rig/lib/mcp-hosts.js:"
rig/lib/renderers.js:7:const { MCP_HOSTS } = require('./mcp-hosts');
```

`materializeSelectedHosts` (`host-capabilities.js:331-353`) builds `entry.mcp`
from `caps.mcp_config` / `caps.surfaces` directly, so `AUTO_WRITE_OVERRIDE`,
`FILE_OVERRIDE` and `LEGACY_FILE` never apply to it. The full gate is green, the
caller-graph test passes, and `api('host-capabilities.js',
'materializeSelectedHosts')` is one of the 68 signed cases — it calls the
diverging function in isolation, which is what the seam guarantees will pass.

The rule to carry into the fix: **a proxy property can be satisfied without
delivering.** Presence, behavior, and existence-of-a-caller are all proxies. The
acceptance test for this ticket is that each new case fails if the *user-visible*
property fails, not if a mechanism is missing.

**3. This ticket alone does not close the loop.** It closes today's instances.
Two generators sit outside its scope and will regenerate work: review has no
finding-class memory ([[RIG-130]]) and "Done" is agent prose rather than a named
green test ([[RIG-131]]). Land those two first — they are cheap, and they are what
makes this ticket's result stick.

## The loop-breaker property, corrected (2026-08-25, third investigation)

**Write contract conformance, not reachability.** Full assessment:
[[2026-08-25-semantic-model-assessment]] §2.

The property this ticket needs is not "these 19 hosts behave correctly" and not
"every `rig/lib` module has a production caller." It is:

> **All host-specific behaviour flows through the host contract.**

Two reasons this is the stronger form:

1. **Reachability is a proxy that is already satisfied while the bug is live.**
   `tests/runtime-caller-graph.test.js` asserts every `rig/lib` module has a
   non-test importer. It is green. `materializeSelectedHosts` still bypasses
   `MCP_HOSTS`. That is rung 2 of the proxy ladder in [[testing-strategy]],
   and rung 3 is the divergence recorded above.
2. **Conformance covers hosts that do not exist yet.** An enumeration covers
   host 1..19; a conformance property covers host 20 before anyone adds it. That
   is what makes it a *class-closing* test rather than 19 more cases.

Reframe the defect the same way. Not *"`materializeSelectedHosts` contains the
wrong value"* but *"a consumer bypassed the semantic boundary."* The first is
one finding; the second is a class with one guard.

This is one of the two architectural fitness functions this project adopts (the
other is the no-second-authority ratchet in [[RIG-132]]) — two, deliberately,
not the seven the source analysis proposes. See
[[2026-08-25-semantic-model-assessment]] §5.

## Sequencing correction (2026-08-25, second investigation)

[[2026-08-25-why-each-pass-finds-new-issues]] measured the finding space and it
changes where this ticket sits in the order.

Every finding this project has received, spec or code, is **pairwise** — "this
place says A, that place says B". Consistency is a property of a pair, so the
defect space is quadratic in the number of places a fact can live: ~124 claim
anchors in the spec is **~7,600 pairs**, against 2–8 findings per pass. The
receipt anchors show the same sections recurring across rounds with *different
partners* (`§8.4` rounds 3 and 5; `§5.7` / `§8.9` / `§11.3` rounds 4 and 5; `§13`
four times in round 5 and again in round 6). Nothing was fixed wrong; a section
has more neighbours than one pass can traverse.

**Consequence for this ticket:** a property test is still a guard over pairs
somebody enumerated. Written over today's N it is another sample. Written after
[[RIG-132]] collapses the duplicate inventory, the same four tests become close
to exhaustive over a much smaller space — the difference between checking a
sample and checking the thing.

So the order is **[[RIG-132]] → this ticket → 126/127/128**, with [[RIG-130]] and
[[RIG-131]] alongside. This does not weaken anything above; it says write these
four tests against one MCP table and one uninstaller rather than against the
collapse itself.

## Low-context implementation packet

**Scope.** This ticket owns the three product properties and the single
authority boundary. Its concrete release defects are implemented on
[[RIG-126]], [[RIG-127]], [[RIG-128]], and [[RIG-134]]. Do not reopen the
test-only `materializeSelectedHosts` debt as a release fix.

**Implementation order.**

1. Land the raw-field ratchet from [[RIG-132]] so no new reader can bypass the
semantic boundary.
2. Make the host-contract writer consume the normalized MCP interpretation and
expose just enough normalized data for a test to compare the renderer and
descriptor outputs. This is behavior parity, not a second table.
3. Make public uninstall delegate to one journal authority, then write the real
bootstrap-to-uninstall roundtrip.
4. Add the staged onboarding public-command roundtrip. It may use a test-only
valid approval receipt, but production must never synthesize approval.

**Tests to write first.** The initial tests are unsigned so the leaf fixes can
follow TDD without editing the owner oracle. After [[RIG-133]] changes the
signed coverage mechanism, promote these exact public-path properties into the
generated signed suite as part of the one owner re-sign; do not copy the tests
into a second hand-maintained oracle file.

| Product property | Initial test | Deterministic assertion |
|---|---|---|
| All host-specific MCP behavior uses the contract | `tests/host-contract-parity.test.js::every emitted MCP descriptor agrees with the interpreted write contract` | Iterate the roster; descriptor disposition, auto-write, path, and key agree with the writer contract for every host. |
| A default install can be fully reversed | `tests/install-uninstall-roundtrip.test.js::public uninstall reverses a default bootstrap install` | Public bootstrap then public uninstall restores the user seed snapshot and removes every Rig-owned path. |
| Printed onboarding actually completes | `tests/runtime-onboarding.test.js::the staged sequence produces review selection plan and a green check` | Execute the installed commands in order with an explicit selection and valid fixture approval; every declared intermediate output is produced and final check succeeds. |

**Completion command.** Run all three named files together, then `npm test`.
The property tests must fail when a consumer bypasses the normalized contract,
when the legacy uninstaller is selected, or when bootstrap again prints an input
with no command that produces it. A unit test that calls only a library export
is insufficient evidence for this ticket.
