# RIG-150 — `.rig/rules/rig.md` points at a path the common install never writes

**Class: CORRECTNESS, mixed (manifest.json gate + markdown wording).**
**Status: OPEN (2026-08-30) — GitHub #127 — found during Path A install-bug investigation.**
Ticket: RIG-150 on [[Tickets]].

## Problem

`rig/tier-1/rules/rig.md` is installed unconditionally
(`host: "neutral"`, no gate — `manifest.json:5`) to every target repo, and
`rig/tier-1/routing.md:3-4` tells every reading agent to "Apply
`.rig/rules/rig.md` to every coding task." The file's one concrete
instruction is:

> For every coding task, read and follow
> `.rig/skills/implementation/SKILL.md`.

But the copy op that writes that exact path (`manifest.json:9`,
`skills/rig/SKILL.md` → `.rig/skills/implementation/SKILL.md`) carries
`"gate": "instruction_only_selected"` — it only fires when the selected
host set includes one of `cursor, windsurf, cline, kiro, gemini, copilot,
antigravity` (`rig/lib/payload.js:11-13`). `claude` and `codex` are the two
`PAYLOAD_HOSTS` not in that list.

Reproduced directly: `sh rig/bootstrap.sh --hosts claude --target <tmp>`
then `ls .rig/skills/implementation` → `No such file or directory`. A
Claude-only or Codex-only install — plausibly the single most common
install shape — ships an "always active" rule whose one instruction points
at a file that was never written.

Partially self-mitigating for a sophisticated agent: instruction-only
hosts (no native by-name skill dispatch, so they *need* the raw path) are
exactly the hosts for which the gate fires and the file exists.
Native-discovery hosts (Claude, Codex — who can route around a missing
path by invoking the skill by name, e.g. `rig-implementation`) are exactly
the hosts for which the file is missing. Not mitigated at all for a
literal-instruction-following instruction-only host without that gate
firing (n/a today, since the gate condition matches exactly the hosts that
need it) — but the reference is still dead weight and a wasted lookup for
every Claude/Codex-only install.

The same dangling reference exists in the dev/source-checkout reading of
this same file content (used directly, unmodified, per `routing.md`'s "in
this source checkout, use `rig/tier-1/rules/rig.md`... instead" clause):
this repo's own checkout has no `.rig/` directory at all, and the correct
source-checkout path per `routing.md:29-31` is `skills/rig/SKILL.md`.
`rules/rig.md` never picked up the source-checkout-vs-installed
conditional pattern `routing.md` otherwise applies consistently to every
other cross-reference in the same payload.

## Location

- `rig/tier-1/rules/rig.md` (whole file, ~5 lines) — the hardcoded path.
- `rig/manifest.json:9` — the gate on the copy op that would satisfy it.
- `rig/tier-1/routing.md:5-8,29-31` — the pattern `rules/rig.md` should
  have followed but didn't.

## Required fix shape

Either:
- Drop the `instruction_only_selected` gate on the tier-1 skill copies so
  `.rig/skills/implementation/SKILL.md` (and its siblings) always land,
  mirroring how vendored skills already always land at `.rig/skills/{name}`
  regardless of host (`manifest.json:44`); or
- Template `rules/rig.md`'s path per the same source-checkout/installed,
  host-aware split `routing.md` already applies elsewhere — e.g. point at
  the skill by name ("read and follow the `rig-implementation` skill")
  rather than a raw file path, which is host-agnostic and survives any
  future gating changes.

Recommend the second: naming the skill rather than a raw path is robust to
whichever hosts get the gated copy in the future, and matches how native
hosts are expected to resolve skills anyway.
