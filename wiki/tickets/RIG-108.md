# RIG-108 — Resolve the four zero-caller runtime modules (wire or delete)

**Status: DESIGNED — decision-ready; one claim in the ticket is now stale.**
Ticket: RIG-108 on [[Tickets]].

## Problem
`enforcement.js`, `graft.js`, `release-evidence.js`, `git-dispatch.js` were said
to be required by nothing outside their own oracle tests — either unwired
features or dead code kept green only by the oracle's direct-`require` binding.

## Findings (verified 2026-08-24 — corrects the ticket)
Precise `require()` search across `rig/`, `scripts/`, `hooks/` (excluding tests):
- **`release-evidence.js` HAS a production caller** — `scripts/review-receipt.js:19`
  requires `catalogueDigest`, `implementationDigest`, `validateReviewReceipt`.
  `review-receipt.js` is the release-review evidence tool. So it is **not**
  dead; it needs a test that reaches it *through* `review-receipt.js`
  (the [[RIG-109]] pattern), not deletion.
- **`enforcement.js`** — genuinely zero-caller. (The `enforcement` hits in
  `policy.js` are a policy-JSON key and a local variable, not a require.)
- **`graft.js`** — genuinely zero-caller. (The `graft` hits in `lint-format.js`/
  `apply.js` are the strings `ci_graft`, `rig-graft`, and a comment.)
- **`git-dispatch.js`** — genuinely zero-caller (no references at all).

## Solution (per module)
1. **release-evidence.js** → *wire-proven*: add an end-to-end test invoking
   `scripts/review-receipt.js` that exercises the digest/validation functions
   through that CLI. No deletion.
2. **enforcement.js, graft.js, git-dispatch.js** → each is a **named product
   capability** (enforcement gate, graft mechanics, git dispatch). Decide per
   module under the owner's re-sign:
   - If the capability ships in the beta scope (D24), wire it into
     `cli-advanced.js`/`materialize.js` behind [[RIG-107]]'s entrypoint and add a
     shipping-path test. `graft.js` most plausibly belongs to the catalogue
     apply path; `enforcement.js` to policy activation; `git-dispatch.js` to
     lifecycle.
   - If out of beta scope, **delete the module and retire its orphaned oracle
     cases** — which edits `wiki/gate1/acceptance.md` (signed) and therefore
     **requires the owner's re-signing ceremony** (same mechanism as [[RIG-102]]).
3. **Invariant test.** Add a meta-test asserting no `rig/lib/*.js` is reached
   only by a direct-`require` oracle test with no production caller — this is the
   acceptance's "no module exercised only by direct-require" guard, and it keeps
   [[RIG-109]] honest.

## What each module actually does (read 2026-08-24, per owner request)
- **`graft.js`** (`ensureManagedBlock(source, name, content)`) — inserts or
  **updates** an idempotent managed block (`<!-- rig:NAME:start -->` … `:end`)
  inside an existing file. This is the mechanic that lets Rig **augment a
  capability the target repo already has** rather than clobber it: e.g. the repo
  already has a code-review skill that only covers certain checks; Rig grafts its
  additional checks onto that file in a delimited, re-updatable block. Owner
  ruling: this is a **headline capability — keep it.** ([[graft-mechanics]],
  Gate 2 §7.)
- **`enforcement.js`** — the **policy enforcement primitive**: `evaluateAction`
  returns allow/deny/disabled for an action against the active policy
  (surface + category), and `consumeOneUseApproval` binds an approval to an exact
  action **digest**, refusing replay or any post-approval change. It is the
  runtime that makes "nothing runs without approval" and one-use approvals real.
  Documented in [[action-evaluator]] / [[one-use-approvals]]; the shipping path
  currently enforces this behavior elsewhere, which is why this module reads as
  zero-caller.
- **`git-dispatch.js`** (`runPreCommit`) — a **pre-commit safety scan** of staged
  agent-instruction/harness files (AGENTS.md, CLAUDE.md, `.cursor/`, `.claude/`,
  `.agents/`, `.kiro/`) for prompt-injection strings and leaked secrets, failing
  closed if `git` itself errors. It defends the exact trust boundary in
  [[sanitation-and-remediation]]: files an agent writes are untrusted input.

## Owner input required
Graft: **keep + wire** (owner confirmed grafting is a headline capability).
Enforcement and git-dispatch: owner has the behaviors above and will decide
wire-vs-delete against D24 beta scope. Deletion of either retires its orphaned
oracle cases in `acceptance.md` (signed) → batch into the [[RIG-120]] re-sign.
