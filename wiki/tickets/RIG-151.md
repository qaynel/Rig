# RIG-151 — routing.md's full-cadence branch asserts a wiki/status.md convention the target repo doesn't have

**Class: POLISH, pure-markdown.**
**Status: DONE (2026-08-31) — GitHub #128 — found during Path A install-bug investigation.**
Ticket: RIG-151 on [[Tickets]].

## Problem

`rig/tier-1/routing.md:22-25`, installed verbatim (no templating) as
`.rig/routing.md` in every target repo:

> Everything else uses the full cadence: read this file, read the wiki,
> read each chosen skill completely, and file a dated reasoning trace then
> regenerate `wiki/status.md` at least every three minutes of active work,
> per `CLAUDE.md`. `(RIG-124)`

Three phantom assertions for a stranger repo: a `wiki/` the target doesn't
have (nothing in `rig/manifest.json` creates one), a cadence the target's
own `CLAUDE.md` doesn't document (the only `CLAUDE.md` mutation for a
Claude host is the one-line `ensure_line` pointer, `manifest.json:28` —
verified by installing into an empty target and reading the result), and
`(RIG-124)`, an internal Rig ticket ID (tracked separately as [[RIG-124.2]]
since the citation pattern itself is a distinct, smaller issue).

What an agent does on hitting this: on the letter of the instruction,
either invents an unrequested `wiki/` + `status.md` cadence in a repo that
never asked for one, or stalls looking for a cadence "per `CLAUDE.md`"
that isn't there. The already-installed `rig-grilling` skill hedges
correctly on the same class of reference —
`rig/tier-1/skills/grilling/SKILL.md:15`: "Check the existing record
first — the wiki, **or a README, reasoning traces, `CLAUDE.md`, or
whatever markdown exists**" — proving the hedge is already a known,
already-used pattern in this same payload. `routing.md`'s full-cadence
sentence just doesn't use it.

## Location

`rig/tier-1/routing.md:22-25`.

## Required fix shape

Rewrite the full-cadence sentence to hedge on the target repo's actual
convention, following `rig/tier-1/skills/grilling/SKILL.md:15`'s pattern:
something like "file a dated reasoning trace in this repo's existing
convention if one exists (a wiki, a README, prior notes) — otherwise skip
this step; it does not apply to a fresh install." Pure prose change, no
code.

**Direction agreed 2026-08-31 (option B):** go past a bare hedge — frame the
passage as an explicit instruction to the onboarding host agent ("this is
Rig's own dev cadence; at install, map it onto this repo's doc convention or
drop it"). Markdown-only, one string read two ways. Not an install-time
`payload.js` transform (rejected), not bare deletion (option A). Bundled with
[[RIG-152]] and [[RIG-124.2]] as one change, one signature.
[[reasoning/2026-08-31-routing-md-adaptation-not-transform]]

**Design filed 2026-08-31** — [[reasoning/2026-08-31-routing-hygiene-design]]
carries the exact reframed wording for the full-cadence paragraph (a "keep a
running reasoning trace" line plus an "Onboarding note" that hands the
map-onto-this-repo's-convention-or-drop-it judgment to the installing host
agent), the coherence follow-on for the task-weight paragraph's stale
"3-minute `status.md` cadence" phrase, and the traced regex conformance.
**Owner approved the wording 2026-08-31** — oracle frozen, `rig-tdd` may
proceed.
