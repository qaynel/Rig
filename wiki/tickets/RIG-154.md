# RIG-154 — AT-HOME-1 OpenClaw fails locally when rig-mcp/node_modules is absent

**Class: PROCESS / LOCAL DEV GAP (no product defect).**
**Status: OPEN (2026-08-31) — GitHub #138 — pre-existing before RIG-153 work.**

## Problem

`npm test` fails locally with:

```
✖ AT-HOME-1 OpenClaw MCP opt-in is explicit, installed, and reversible
AssertionError: rig: npm ci failed for bundled rig-mcp runtime:
  cp: .../rig-mcp/node_modules: No such file or directory
```

The root oracle (`tests/advanced-oracle.test.js`) exercises the bundled
MCP runtime as part of the `AT-HOME-1` OpenClaw test, which bundles
`rig-mcp/node_modules` into a temp dir. If `rig-mcp/node_modules` has
never been installed locally, that `cp` fails and the test exits 1.

## Why CI is green

`.github/workflows/test.yml` has an explicit step that runs before
`npm test`:

```yaml
- name: Install bundled MCP runtime dependencies
  run: npm ci --prefix rig-mcp --no-audit --no-fund
```

Comment in the workflow: "The root oracle exercises the bundled MCP runtime
before the runtime project's own pretest hook runs, so install it explicitly
first." Local dev environments that skip this step will see the failure.

## Impact

- **CI**: green (prerequisite step always runs).
- **Local `npm test`**: red until `npm ci --prefix rig-mcp` is run once.
- **No product defect.** The test, the workflow, and the MCP code are all
  correct. This is purely a local dev ergonomics gap.

## Fix

One of:

1. **Immediate workaround** (one-time per workspace): `npm ci --prefix rig-mcp`
2. **Durable fix**: add the prerequisite to `CLAUDE.md` under the Checks
   section, so any agent or developer starting fresh runs it before the
   first `npm test`. Optionally wire it into a `setup:dev` or `pretest`
   script — but that adds ~5–10 s to every `npm test` run, so document
   first and decide on automation separately.

## Acceptance

1. `npm test` passes locally (559+/0 fail) in a workspace where
   `rig-mcp/node_modules` was not pre-installed, **OR** the prerequisite
   is prominently documented so it is never the cause of a surprise red run.
2. The fix does not add a mandatory slow step to the fast inner-loop
   (`npm run test:rig`).

## Evidence

- Failing test: `tests/advanced-oracle.test.js:548`
- CI prerequisite: `.github/workflows/test.yml` step "Install bundled MCP runtime dependencies"
- First observed: pre-existing on `qa-prod-v5` before RIG-153 instrument work (2026-08-31)
