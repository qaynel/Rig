# RIG-143 — runGrade runs approved commands with no network isolation

**Class: CORRECTNESS / SHELL TRUST.**
**Status: COMPLETE (2026-08-28) — GitHub #111 closed (#102/#107).**
Ticket: RIG-143 on [[Tickets]].

## Problem

`runReadOnly` wraps every command's argv through `argvWithNetworkIsolation`
(`unshare`/`sandbox-exec`) and refuses to run when neither isolation tool is
available. `runGrade` — the path that runs the repo's own lint/format/`make`
commands — called `runCommand` with raw argv: no isolation prefix, no refusal.

AT-LF-22's frozen acceptance text says "an approved command … not explicitly
granted network access by the plan," not "a read-only command." Both
`runReadOnly` and `runGrade` execute approved commands, so the guarantee
reads as covering both paths. `runGrade` has no production caller yet
(grep confirms only test/comment references), so this was latent — but it
blocked signing AT-LF-22 as implemented while the gap stood.

`tests/guarantee-coverage.test.js` (`AT-PROC-1`) already covers two other
`runGrade` parity gaps from the same guarantee-sharding pattern —
`AT-PROC-1b` (cwd containment, AT-LF-21/24) and `AT-PROC-1c` (memory ceiling,
AT-LF-23) — but not the network conjunct. See
[[mistakes/guarantee-sharding]].

## Location

`rig/lib/lint-format.js`:
- `runGrade` — called `runCommand(cmd.argv, ...)` directly, with no isolation
  prefix or per-command network-grant handling.
- `runReadOnly` and `argvWithNetworkIsolation` — the reference implementation
  to mirror, including RIG-141's per-command gating (`network: true` bypasses
  both the prefix and any refusal).

## Grilling record

Full context, options considered, and the two decisions resolved:
[[reasoning/2026-08-28-runGrade-network-isolation-grilling]].

## Required fix shape

- `runGrade` composes each command's argv through the same
  `argvWithNetworkIsolation` used by `runReadOnly`.
- When isolation is unavailable for an ungranted command, `runGrade` reports
  a non-passing state (mirroring `runReadOnly`'s
  `network_isolation_unavailable`), gated **per command** exactly like
  RIG-141's fix — a `network: true`-granted command still runs even when no
  sandbox tool is present.
- Rejected: having Rig detect and offer to install missing sandbox tooling.
  The documented CI failure mode
  ([[reasoning/2026-08-28-linux-network-isolation-ci]]) is a denied kernel
  capability (AppArmor blocking unprivileged user namespaces on a locked-down
  host), not a missing binary. No install closes a host-policy capability
  denial.
- `tests/guarantee-coverage.test.js` gains `AT-PROC-1d`, the network parity
  test on the `runGrade` path.
- `AT-PROC-1c`'s fixture is marked `network: true` so it stays on the
  unprefixed path and continues testing memory independently.

## Acceptance

- A `runGrade` command with no explicit network grant cannot reach an
  outbound listener (parity with the existing `AT-LF-22` `runReadOnly` case).
- A `runGrade` command with `network: true` still runs and is unaffected,
  including when no sandbox tool is present on the host (parity with RIG-141).
- When isolation is unavailable, an ungranted command reports
  `network_isolation_unavailable` and the grade is non-passing.
- `AT-PROC-1d` is added to `tests/guarantee-coverage.test.js`, red against
  the old `runGrade` and green after the fix.
- `AT-PROC-1c` continues to pass, unaffected by the isolation change.
- No frozen file (`tests/advanced-oracle.test.js`,
  `wiki/gate1/testing-infrastructure.manifest`) is edited; no oracle re-sign
  is required.
