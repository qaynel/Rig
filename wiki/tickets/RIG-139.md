# RIG-139 — AT-LF-24 symlink containment only wired in `runReadOnly`; `runGrade` uses `cmd.cwd` unguarded

**Class: CORRECTNESS / SHELL TRUST.**
**Status: OPEN (2026-08-27) — GitHub #94.**
Ticket: RIG-139 on [[Tickets]].

## Problem

AT-LF-24 requires that tasks cannot escape the repository through symlinks.
The fix wired the boundary check into `runReadOnly` only: at
`rig/lib/lint-format.js:616–619`, `taskCwd` (which calls `containedPath` and
throws on escape) guards the `cwd` before the command runs.

`runGrade` — the function that actually executes lint and format checks — does
not go through `taskCwd`. At line 527–528 it passes `cmd.cwd` directly:

```js
const result = spawnTask(cmd.argv, {
  cwd: cmd.cwd || process.cwd(), timeout: cmd.timeout_ms || 10 * 60 * 1000,
});
```

A command object whose `cwd` resolves outside the repository root (via a
symlink or a relative path like `../../etc`) will run with that unguarded
working directory. The same escape AT-LF-24 closed on the read-only path is
fully open on the path that does the real work.

## Location

`rig/lib/lint-format.js` — `runGrade`, lines 527–528. The fix for `runReadOnly`
is at lines 615–619 (`taskCwd` / `containedPath`). `runGrade` needs the same
treatment.

## Acceptance (draft — not yet reviewed or signed off)

- A `runGrade` invocation whose command specifies a `cwd` that escapes the
  target repository root (directly or via a symlink) is refused with a
  `boundary_violation`-equivalent result, matching the behaviour already
  present in `runReadOnly`.
- A `runGrade` invocation with a legitimate in-repository `cwd` runs normally.
- A new test title covering the `runGrade` escape path is added to
  `tests/advanced-oracle.test.js` (or equivalent) before any implementation
  lands.
