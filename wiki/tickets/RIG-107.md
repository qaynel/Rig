# RIG-107 — Wire the advanced runtime into a real install/run entrypoint

**Status: DESIGNED — implementation-ready (core release blocker).**
Ticket: RIG-107 on [[Tickets]].

## Problem
`rig/materialize.js` orchestrates the whole à-la-carte engine (`inspect`,
`recommend`, `plan`, `apply`, `remediate`, `check`, `policy`, `uninstall`) via
`cli-advanced.js`, but nothing invokes it in a shipping flow: `bootstrap.sh` and
`install.sh` only run `rig/lib/payload.js` (static markdown copy).
`materialize.js` installs as an inert file (`.rig/runtime/rig/materialize.js`,
`active_delivery` gate) with no wrapper, bin, or documented command. A customer
cannot reach the catalogue/policy/safety runtime the product's core promise is
built on.

## Findings
- `materialize.js` legacy no-subcommand path does MCP config; subcommands
  delegate to `cli-advanced.js` → `inspect/profile/plan/apply/checks/catalog/
  policy/lifecycle`. The wiring exists; only the **entrypoint** is missing.
- `bootstrap.sh` line 73 requires `rig/lib/payload.js` directly; `--with-runtime`
  copies runtime files but adds no callable command.
- README already documents `node rig/materialize.js <cmd>` and
  `node .rig/runtime/rig/materialize.js` for tagged installs — but there is no
  installed bin/shim, so it is "read the source" reachable only.

## Solution (installed entrypoint + onboarding + regression)
1. **Installed shim.** When `bootstrap.sh --with-runtime` runs, drop a small
   executable `.rig/bin/rig` (POSIX sh, no Bash) that `exec node
   "$(dirname)/../runtime/rig/materialize.js" "$@"`. Record it in
   `.rig/install-manifest.jsonl` like every other write. This gives a supported
   `.rig/bin/rig inspect|recommend|plan|apply|check` surface without a global
   install, satisfying "documented entrypoint drives materialize.js end to end."
2. **Onboarding surfaces it.** After a `--with-runtime` install, print the
   inspect→recommend→plan→apply→check sequence with the `.rig/bin/rig` prefix so a
   stranger runs it without reading source (mirror the README block).
3. **Regression through the shipping path.** Extend the distribution/bootstrap
   test: install `--with-runtime` into a temp repo, then execute at least one
   catalogue leaf (lint-format) **through `.rig/bin/rig`** (not `require`), and
   assert the check binding lands (`.rig/service-bindings.json` + `.rig/bin/check.js`).
   This is also the vehicle [[RIG-109]] needs.

## Constraints
Tier 1 stays markdown-only — the shim + runtime land **only** under
`--with-runtime`/tagged install, never in a default local bootstrap. No secrets,
no `.env`. `.rig/bin/rig` is POSIX sh (matches the `install.sh` POSIX stance).
