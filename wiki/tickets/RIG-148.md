# RIG-148 — Default install lands unignored: 209 files / 8.3 MB with no `.gitignore`

**Class: DELIVERABILITY / ONBOARDING HYGIENE.**
**Status: DONE (2026-08-31) — GitHub #125.**
Ticket: RIG-148 on [[Tickets]].

## Problem

Neither `rig/lib/payload.js` nor `rig/bootstrap.sh` writes or merges a
`.gitignore` entry for anything the installer creates. Measured directly
(`sh rig/bootstrap.sh --hosts claude --target <disposable-tmp-dir>`): a
default, markdown-only, single-host install lands **209 files / 8.3 MB**,
and `git init && git add -A && git status --short` shows all 209 paths as
`A` — nothing is ignored. This holds with zero `--with-runtime` content;
the size comes from the vendored skill catalog landing twice (see
[[RIG-149]]'s sibling finding in the same investigation, and
[[topics/graft-mechanics]]).

The next commit a Rig user makes in a freshly-bootstrapped repo will, by
default, check in the entire `.rig/` tree plus every host-specific skill
mirror, unless they know to hand-write the ignore rules themselves first.

## Decision needed (owner, not this ticket's to make alone)

Two coherent designs:

- **Gitignore (tool-cache model).** `.rig/`, `.claude/skills/rig-*`,
  `.agents/skills/rig-*` are regenerable local tooling — never committed,
  re-synced by rerunning `bootstrap.sh`. Diffs stay clean; nothing about
  Rig shows up in code review. Cost: invisible to a teammate who doesn't
  bootstrap themselves, and to any CI job reading config only from the
  committed tree.
- **Commit (vendored-config model).** Treat the payload as reviewable,
  versioned repo content, like `.eslintrc` or `.github/workflows/`. Cost:
  every Rig version bump is a multi-hundred-file diff in every downstream
  repo, and the [[RIG-149]]-adjacent duplication becomes permanent bloat.

Recommendation: gitignore, since Tier 1 describes itself as installing "a
curated markdown-only agent workflow" — re-derivable at any time from the
pinned release — not repo-authored content.

## Location

- `rig/lib/payload.js` — `runPayload()` (no `.gitignore` write in the
  payload loop, `:233-261`).
- `rig/bootstrap.sh` — no post-install step touches `.gitignore`.
- `rig/manifest.json` — no payload entry targets `.gitignore`.

## Required fix shape (pending the decision above)

- If gitignore: add a payload entry (new `op`, e.g. `ensure_gitignore_block`)
  that appends a named, idempotent block covering `.rig/` and the
  host-specific `rig-*` skill directories — mirroring the existing
  `ensure_line` managed-block pattern already used for `CLAUDE.md`/
  `AGENTS.md`/`GEMINI.md` pointers (`manifest.json:28,34-36`).
- If commit: no code change; document the decision in
  [[topics/graft-mechanics]] and close this as a decision record, not an
  implementation ticket.

## Acceptance

- A fresh default install followed by `git status --short` shows either
  (a) zero untracked Rig-owned paths (gitignore path), or (b) the decision
  to commit is recorded in the wiki with the tradeoff stated (commit path).
- The fix is idempotent: re-running bootstrap does not duplicate the
  `.gitignore` block.
- New regression test in `tests/rig-bootstrap.test.js` (or a new file)
  asserting the chosen behavior.
