# RIG-119 — Incorporate spec-driven development into the Rig pipeline

**Status: DECIDED (2026-08-24) — fold in, no new skill. Follow-through not yet
implemented.**
Ticket: RIG-119 on [[Tickets]].

## Decision
Owner approved the recommendation below: fold spec-driven development into
`rig-grilling`/`rig-product-design`; no new routing-table row. Remaining work
is the follow-through text edit (see "Why this is deferred" below, now the
implementation task).

## Problem
The spec toolkit's five-phase "turn vague intent into a precise, executable
spec" flow overlaps Rig's `rig-grilling` → `rig-product-design` → gate pipeline
but isn't a first-class Rig capability. Bringing an executable-spec authoring
flow into the routing table would strengthen the front of the pipeline.

## The decision (one question for you)
Does spec-driven development become **its own Rig skill/graft**, or is it
**folded into `rig-grilling`/`rig-product-design`**? Scope is bounded to
markdown-only Tier 1 either way.

## My recommendation: fold it in, don't add a skill
- `rig-grilling` already owns "business intent, acceptance criteria, and the
  testing infrastructure that deterministically checks them" — that *is* an
  executable spec. `rig-product-design` owns the technical spec. A separate
  spec skill would overlap both and dilute the "one owner per phase" routing
  discipline the router enforces ("do not substitute a nearby skill for the
  named owner").
- Concretely: import the strongest bits of the five-phase flow (the
  vague-intent→examples→testable-criteria progression) as guidance *inside*
  `rig-grilling`, and reference the executable-spec framing in
  `rig-product-design`. No new routing-table row.
- If instead you want it discoverable as a named entry (e.g. customers ask for
  "/spec"), the minimal adoption is a thin `rig-spec` graft that routes into
  grilling — but that's a marketing/discoverability call, not an architectural
  need.

## Why this is deferred, not resolved
The acceptance says "a decision is recorded on whether spec-driven development
becomes a Rig skill/graft or is folded in." That decision is yours. Once you
pick, the follow-through is small (routing-table + skill-index text, or a graft
+ one acceptance case) and I can land it. If rejected, I file the reasoning.
