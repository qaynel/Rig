# RIG-147 — Undeclared-network diagnostic is written to stderr via console.warn on top of the structured result field

**Class: ARCHITECTURE / DIAGNOSTIC HYGIENE (minor).**
**Status: OPEN (2026-08-29) — GitHub #110 — accepted follow-up from the passing v5.0.0 review; non-blocking.**
Ticket: RIG-147 on [[Tickets]].

## Problem

`runConfiguredArgv` (`rig/lib/check-runner.js:196-200`) handles the
`undeclared` network state per AD-39 / `GA-38`: it runs the command without
an isolation prefix and returns the structured fields
`network_state: 'undeclared'` and `diagnostic: '…'`. `AT-CAP-3` and
`AT-PROC-1u` (`tests/guarantee-coverage.test.js`) assert those fields.

It **also** calls `console.warn(diagnostic)`. That is a side-channel emission
to the runner's own stderr: in CI it interleaves with the checked command's
output and callers that consume the structured return object can miss it
entirely. `status` correctly stays whatever the command exited with
(undeclared is deliberately not a named non-passing result, so the ~115
un-audited catalog packs keep working — [[RIG-144]], AD-39).

The spec asks for "a visibly reported compatibility state." The structured
fields already satisfy that; the `console.warn` is redundant and noisy.

## Location

`rig/lib/check-runner.js` `runConfiguredArgv` (`:173-202`), the
`network === 'undeclared'` branch at `:196-200`.

Consumers of the return value:
- `rig/lib/checks.js` (`rig check` subcommand)
- `rig/catalog/baseline/check.js` → `.rig/bin/check.js` (installed CI runner)
- the CI adapters that shape the workflow output

## Required fix shape

- Drop the `console.warn` from the `undeclared` branch; keep the structured
  `network_state` + `diagnostic` return fields.
- The installed CI runner / CI adapter routes `network_state === 'undeclared'`
  from the return value into a visible workflow annotation (one clear
  surface, not stderr noise).
- No spec change, no oracle change.

## Acceptance

- `runConfiguredArgv` on an undeclared-network binding still returns
  `network_state: 'undeclared'` and a matching `diagnostic` string;
  `AT-CAP-3` and `AT-PROC-1u` still pass.
- No write to stderr from the `undeclared` branch itself.
- The installed CI path surfaces the undeclared state visibly from the
  structured field (new/updated test in `tests/guarantee-coverage.test.js`
  or the CI-adapter suite).
- No frozen file edited.
