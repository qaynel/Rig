# Close-out: fresh-checkout `npm test` bootstrap (RIG-154)

Design and mechanism:
[[reasoning/2026-08-31-rig-154-fresh-checkout-npm-test-design.md]]. This trace
records what landed and the acceptance evidence.

## What shipped (PR #140, commit `a15d4267`)

- **D1 — `package.json` `pretest`.** Now brace-grouped:
  `{ <venv-guard>; } && { [ -d rig-mcp/node_modules ] || npm ci --prefix rig-mcp --no-audit --no-fund; }`.
  The mcp guard runs `npm ci` only when the tree is absent, mirroring the
  venv guard's "check or build" precedent.
- **D2 — `tests/rig-mcp-bootstrap.test.js`** (non-frozen, 2 assertions):
  the `pretest` guard is present and correctly shaped; `.github/workflows/test.yml`
  carries no `npm (ci|install) --prefix rig-mcp` step that would mask a broken
  guard. Both fail before D1/CI change, pass after.
- **CI parity.** The standalone "Install bundled MCP runtime dependencies"
  step was deleted from `.github/workflows/test.yml`; local and CI now run the
  one `pretest` bootstrap.
- **Gate-1 re-sign (done in the same PR, by the human key holder).**
  `wiki/gate1/package-scripts.json` (in the signed manifest) was updated to the
  new `.scripts` snapshot; `wiki/gate1/testing-infrastructure.manifest` digest
  refreshed; `wiki/gate1/gate1.sig` re-signed and `wiki/gate1/gate1.allowed-signers`
  moved to an `ssh-ed25519` key. `node scripts/check-advanced-spec.js` →
  *Oracle verified: 5 files, 73 acceptance cases*, exit 0, on `a15d4267` and on
  a fresh clone of it. No further re-sign is owed — the
  `--confirm-digest-delta 1408f38…` step in the original close-out handoff
  described the pre-merge draft state and must not be re-run.

no `rig-mcp/node_modules` (both confirmed absent; `git check-ignore
rig-mcp/node_modules` → ignored). Then `npm install` (ordinary fresh-clone
step, not under test) followed by `npm test`.

Notes on the evidence:

- **`npm test` exits 0 on a cold checkout.** The `pretest` venv guard and mcp
  guard each fired exactly once (first `pretest` run); the `pretest:code` re-run
  was a no-op, confirming idempotency.
- **AT-HOME-1 passes** — the frozen case that needed `rig-mcp/node_modules` to
  exist before the oracle runs. Its 27.7 s runtime is the real MCP client
  connecting to the installed server and calling `rig_instructions`, so the
  bootstrapped tree is genuinely functional, not a stub.
- **`rig-mcp/node_modules` stays untracked** — it does not appear in
  `git status`; it is git-ignored. The one untracked path, root
  `package-lock.json`, is written by the `npm install` bootstrap step (this repo
  does not commit a root lockfile) and is not produced by `npm test` or the
  `pretest` guard. Not a RIG-154 regression.
