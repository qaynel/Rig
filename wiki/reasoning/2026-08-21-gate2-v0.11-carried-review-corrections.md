# Gate 2 v0.11 — carried round-5 mechanism corrections

The round-5 review identified four mechanism defects that remained applicable
after D22, D23, and v0.10 resolved the other findings. They can be corrected
without changing any Gate 1 verdict.

## Evidence and CI are separate states

Gate 1 defines Evidence by a verifiable result and defines its CI behavior in a
separate case that requires a separately approved graft when CI is absent. Gate
2 had made the graft a constituent check of Evidence, making Evidence
logically unreachable before the separate approval. v0.11 makes the local
Evidence verdict depend on locally captured, rerunnable evidence and treats CI
as its independent repository enforcement surface. CI absence remains visible;
it does not downgrade a completed local result.

## Remediation rollback has journal semantics

Install failure deliberately retains applied writes for resume. Remediation
failure deliberately rolls back. Calling both the same transaction path left
rolled-back writes recorded as live install artifacts. v0.11 keeps one
append-only journal but names the transaction kind. Successful remediation is
a retained user-approved content edit excluded from uninstall; rollback appends
a terminal record with the restored digest; crash reconciliation accepts only
the exact expected output or exact preimage and blocks every third state.

## Recovery registration fails closed

The recovery ceremony relies on requesting authenticator user verification.
"Where the platform exposes it" left an undefined weaker path. v0.11 refuses
registration with `user_verification_unavailable` when that request cannot be
made. Automation still does not claim to prove a hardware touch; it can prove
the requested mode or the refusal and disclose the declared class.

## Abnormal results belong to the schema

Gate 2 required six distinct abnormal outcomes while its closed report enum
permitted only three states. v0.11 adds all six to the report schema and keeps
them non-passing and distinct, matching the acceptance case instead of forcing
the validator to collapse them into generic failure.

The separate round-5 finding that most traceability rows name no executable
target remains open. It belongs to the complete testing-infrastructure pass and
must be resolved before the oracle is signed.
