# Grill turn 2 — "remove the allowed-signers list"

Follows `2026-09-02-gate1-allowed-signers-comment-preservation-grill.md`.

## What the owner said

> We don't need any allowed signers list, remove that. Any sort of key applied
> on Gate 1, which is only generated by humans, is good enough.

## Why removing the pin was rejected

- `ssh-keygen -Y verify` verifies a signature **against a named public key**.
  There is no meaningful "any key" mode. `ssh-keygen -Y check-novalidate` only
  confirms the blob is internally well-formed against the public key the signer
  embedded in it, so it passes for any self-consistent signature.
- The premise "keys on Gate 1 are only human-generated" is false in the threat
  model. The Gate 2 implementation agent has repo write access. With no pinned
  key it runs `ssh-keygen -t ed25519`, signs `oracleMessage(root)` with the new
  key, writes `gate1.sig`, and `check-advanced-spec.js` passes. The gate becomes
  forgeable by the agent it is meant to constrain.
- The pinned public key is the one artifact in the repo the agent cannot
  satisfy — it lacks the matching private key. That is the whole mechanism
  (hub "Why it is this way"). Removing it is not a simplification, it is
  removing Gate 1 integrity.

This is now recorded as a rejected approach: **"Gate 1 verifies any signature,
no pinned key."** Reason: trivially forgeable by a repo-writing agent.

## What the owner's instinct does justify

The friction is real: one signer, always `gate1-owner`, wrapped in a "list"
file that also carries hand-written provenance comments the ceremony overwrites
on every re-sign.

**Narrowed proposal (recommended, awaiting owner confirm):** make
`gate1.allowed-signers` a purely generated one-line file — the pinned key, no
comments. Key-class / rotation provenance lives only in
`wiki/topics/gate1-signing.md`, where it already mostly is.

- The comment-clobber defect disappears (nothing to preserve).
- No new script logic — strictly less than the turn-1 fix.
- Gate integrity unchanged: the key is still pinned, `ssh-keygen -Y verify -f`
  still runs against it.
- One-time: delete the five-line `# key-class:` block from the file; confirm the
  hub carries that history (it does, "Standing" section).

Alternative kept on the table: turn-1's fix (script preserves `#` and blank
lines). Keeps provenance beside the key at the cost of script logic. Weaker fit
now that the owner has asked for less machinery.
