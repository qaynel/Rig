## Finding A — the tickets' cited reasoning traces do not exist in the repository

Each of RIG-125, RIG-130, RIG-132, RIG-133 links `[[...]]` to a set of eight
2026-08-25 reasoning documents:

- `2026-08-25-branch-code-review-snapshot`
- `2026-08-25-rig120-review-round3-receipt`
- `2026-08-25-rig120-round3-finding-map`
- `2026-08-25-structural-nondeterminism-root-cause`
- `2026-08-25-why-each-pass-finds-new-issues`
- `2026-08-25-semantic-model-assessment`
- `2026-08-25-escaping-the-quadratic`
- `2026-08-25-prev5-classification-and-migration-pattern`

None of these files exist under `wiki/reasoning/` on disk. `find wiki -iname
"*<slug>*"` returns nothing for all eight. `git log --all --diff-filter=A` shows
they were never added by a real commit on any ref — the only commits that touch
these paths are Conductor session-checkpoint commits from 2026-08-25 (worktree
snapshots of a session that had them as uncommitted files). Checked every real
branch (`origin/prod`, `rig-120-release-ceremony`, `rig-126-onboarding-e2e`,
`rig-127-followup-docs`, `rig-128-mcp-contracts`, `rig-129-claim-accuracy`,
`rig-134-prev5-gate`, `rig-135-subprocess-cleanup`, `uninstall-orphan-cluster`,
`qa-prod`, `qa-prod-finishing-up`, `qa-prod-finishing-up-v1`, `amman`): zero
matches everywhere.

The four ticket files themselves landed on this branch via `da4a41e` ("Add
pre-v5 acceptance test baseline"), which added the four ticket bodies (already
containing these links) but added none of the eight reasoning files. So the
citations were dangling at the moment they were committed here — the underlying
analysis sessions ran in a different, uncommitted workspace and the trace files
were lost before anyone ran `git add` on them.

This is a live violation of `wiki/reasoning/README.md` ("a trace is written
once ... never edited" — implying it is committed) and of `CLAUDE.md`'s "a wiki
that has drifted from the branch is a defect, not stale documentation." The
ticket bodies are still readable and self-contained (they quote their own
grep output, tables, and code snippets inline), so no conclusion in them is
unverifiable on that account — but "Analysis: [[...]]" now points at nothing,
and a reader following the citation trail hits a dead end at exactly the point
they'd expect the full reasoning.

**This is an owner decision, not one this pass makes silently:** either the
original session transcripts are recoverable and the eight traces get filed
verbatim (as the convention requires — traces are never reconstructed from
memory, only filed as originally written), or the tickets' `[[...]]` citations
to these eight names are struck and replaced with a note that the analysis was
lost pre-commit, with the surviving inline evidence in the ticket body treated
as the whole record going forward.
