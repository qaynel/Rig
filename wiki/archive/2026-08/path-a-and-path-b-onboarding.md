# Path A and Path B: the adaptation eval, the install bugs, and agent-led adaptive onboarding

Compacted on 2026-10-17 from 13 August 2026 reasoning traces. Bodies live in
git history; every decision, rejection, trap and verbatim owner ruling the
sources carried is reproduced below.

## What this theme settled

The first real adaptation run scored **+12/100** on `claude-task-master-main`,
and its one-line verdict became the project's reference finding: **merge works;
adapt does not**. Config preservation was near-perfect (one append with a stored
preimage, zero overwrites), but Rig treated a repo with 27 Cursor rules, 5 Kiro
steering docs, a Claude plugin and `.taskmaster/CLAUDE.md` as if it were empty,
stacked generic files in parallel across three ecosystems, and shipped ~85%
dead-weight skills by count.

The owner set the order: **Path A first** (fix the concrete install bugs and
freeze a real measurement instrument), **then Path B** (build adaptive
integration), with **Path C** (real-user testing) running async. A code-confirmed
correction landed immediately: the eval scored a `--with-runtime` install, not
the default; the default is markdown-only. Path A's own investigation then
measured the real default install at **209 files / 8.3 MB, 100% unignored**, and
found two new correctness bugs beyond the known phantom-text traps — a dangling
`.rig/skills/implementation/SKILL.md` reference and a `rig` → `rig-rig` name
collision for native-dispatch hosts.

Path B was first scoped as "deterministic acceleration" in the owner's own
words: Rig ships deterministic tools the host agent invokes; the agent and user
own the judgment; D24 stays intact. Two eval premises were withdrawn — no
deletion in either direction (the fix is selective install, not
install-all-then-prune), and the install must be context-weight neutral or
negative. Six buildable items (B-1..B-6) were separated from four
grilling-gated ones (G-1..G-4) and three deferred features (DF-1..DF-3).

The owner then locked Path B as **agent-led adaptive onboarding**: the host
agent, given full repository and Rig capability context, grafts the smallest
useful set onto existing infrastructure; the user reviews the resulting
improvement and only genuinely critical decisions; Rig code still does not
infer; the router re-test is deferred and does not block. Seven decisions
followed (families not a flat catalogue; repo-specific state under `.rig/`;
agent-led selection not a wizard; payload weight as warning-only with hard
failures reserved for correctness regressions; the onboarding agent performs
the intelligence; graft onto existing infrastructure by calculating the delta;
and an eight-section onboarding summary). The follow-up locked graft mechanics
(explicit machine-detectable begin/end ownership markers in repo-owned files)
and the skill-shelf reorganisation (family → tool/capability → skill, by
capability not vendor origin), leaving the governed 115-service catalogue's
`family → group → service → grade` untouched and taxonomy unification deferred.

A full technical specification (F-1..F-6, S-1..S-4) followed, then a ten-case
acceptance oracle expanding Gate 1 to 83 IDs with 55 direct checks producing 54
expected product failures and one deliberately green service-catalogue
preservation guard — handed to the human signature with implementation not begun.

`routing.md`'s phantom-convention text was fixed by reframing it as explicit
instructions to the onboarding host agent, not by an install-time transform
(rejected) and not by bare deletion. RIG-153 closed with the measurement
instrument delivered and frozen; the re-baseline run was carved out as RIG-156,
deferred until Path A and Path B are fully decided.
