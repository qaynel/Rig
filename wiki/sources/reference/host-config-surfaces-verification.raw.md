# Rig Host Configuration Surfaces — Per-Host Verification Report

**Scope note:** REPO/PROJECT-scoped = committable inside a target git repo. USER-GLOBAL = home directory, not committable per-repo. Findings are labeled **OFFICIAL** (vendor doc / official README / changelog) vs **COMMUNITY** (blog / third-party / forum). Every finding cites its source URL.

## TL;DR
- **Committable per-repo MCP config EXISTS for:** Antigravity (`.agents/mcp_config.json`), Gemini CLI (`.gemini/settings.json`), Devin **CLI** (`.devin/config.json` → `mcpServers`), Swival (`.swival/mcp.json` or `swival.toml [mcp_servers.*]`), and Cursor (`.cursor/mcp.json`). It does **NOT** exist (user-global only) for Devin **Desktop** (ex-Windsurf), Cline, Hermes, and CodeWhale; and MCP is unsupported by design for pi and (per your note) permanently for pi.
- **Two prior hypotheses must be REVERSED:** pi **does** auto-discover skills (`.agents/skills/`) and Cursor **does** document an auto-discovered skills directory (`.cursor/skills/`) — neither should be marked "skills NOT SUPPORTED." Also "Devin" must be split into cloud Devin (marketplace/trigger-only) vs Devin CLI (full committable `.devin/` surface).
- **Native blocking hook frameworks are VERIFIED for:** Antigravity (`.agents/hooks.json`, deny/ask), Gemini CLI (`.gemini/settings.json`, deny/exit-2), Devin Desktop/Cascade (`.windsurf/hooks.json`, pre-hooks block via exit 2), Devin CLI (`.devin/hooks.v1.json`), CodeWhale (`.codewhale/hooks.toml`, allow/deny/ask), Cline (`.cline/hooks/`), and Hermes (`~/.hermes/hooks/…HOOK.yaml`). Swival has **startup/exit-only** hooks (no edit-time gate; use command middleware). pi has no `hooks.json` — only TypeScript extensions.

## Details

### 1. ANTIGRAVITY (Google Antigravity — Antigravity 2.0 / CLI / IDE / SDK)
**Identity / unification (OFFICIAL + COMMUNITY):** Google's agent-first suite. At Google I/O 2026 the Gemini CLI was folded into the suite as the Go-based "Antigravity CLI" (Gemini CLI deprecation for free and Pro/Ultra tiers June 18, 2026). Antigravity 2.0, CLI, IDE, and SDK share one agent harness and unified config under `~/.gemini/`. Sources: antigravity.google/docs; medium.com/google-cloud "Configuring MCP Servers and Skills for Antigravity CLI and IDE" (COMMUNITY).

- **(a) Event hooks — VERIFIED (OFFICIAL).** Framework file: `hooks.json` in the customization dir — `.agents/` in the workspace (repo-scoped, committable) or `~/.gemini/config/` (global). Events: `PreToolUse`, `PostToolUse`, `PreInvocation`, `PostInvocation`, `Stop`. **Blocking = YES.** Per antigravity.google/docs/hooks, hook scripts "print a JSON response on stdout telling Antigravity whether to 'allow', 'deny', or 'ask' for user confirmation" (PreToolUse also supports `force_ask`); inputs arrive on stdin as JSON "containing context like the tool arguments (toolCall.args), active workspacePaths, and the filepath of the current session log (transcriptPath)." `Stop` hooks can return `decision:"continue"` to force the loop to keep running; `PostInvocation` supports `terminationBehavior: force_continue|terminate`. Matcher is a regex over tool names for the two tool events, ignored for the others. Source: https://antigravity.google/docs/hooks
- **(b) Always-on instruction FILE — VERIFIED (OFFICIAL).** Repo-scoped project rules live in `.agents/rules/<name>.md` (workspace/git root; legacy fallback `.agent/rules/`). Activation modes: Manual, Always On, Model Decision, Glob. Global rules: `~/.gemini/GEMINI.md`. Antigravity also reads root `AGENTS.md`/`GEMINI.md` for context. Source: https://antigravity.google/docs/rules-workflows. **Caveat:** the exact frontmatter `trigger: always_on` is not shown verbatim on the official Rules page (which uses the GUI label "Always On"); that YAML key is COMMUNITY-corroborated (dev.to guides; shared Windsurf lineage) and should be verified in-product. The officially-grounded append target is any file under `.agents/rules/`.
- **(c) PROJECT-scoped MCP — VERIFIED (OFFICIAL).** Committable workspace file: `.agents/mcp_config.json`; user-global equivalent `~/.gemini/config/mcp_config.json`. Both use a top-level `mcpServers` object; remote servers must use `serverUrl` (legacy `url`/`httpUrl` unsupported); supports `disabled`, `disabledTools`, `authProviderType`, `oauth`. SDK auto-discovers `.agents/mcp_config.json`. Source: https://antigravity.google/docs/mcp. **Caveat (COMMUNITY):** for the *Antigravity CLI* specifically, github.com/google-antigravity/antigravity-cli issue #60 reports the project-local `.antigravitycli/mcp_config.json` is discovered but its `mcpServers` is silently ignored — only the HOME config spawns servers. The IDE/SDK `.agents/mcp_config.json` path is the reliable committable one.
- **Bonus (OFFICIAL):** repo-scoped skills at `.agents/skills/<name>/SKILL.md` (fallback `.agent/skills/`; global `~/.gemini/config/skills/<name>/`). Source: https://antigravity.google/docs/skills.

### 2. WINDSURF → DEVIN DESKTOP (Cognition; Cascade EOL 2026-07-01)
**Rebrand (OFFICIAL + COMMUNITY):** Windsurf became **Devin Desktop** via OTA update on June 2, 2026 (shipped as build 2026.5.26, per zemith.com — COMMUNITY). Per Cognition's FAQ, "plans, pricing, settings, extensions, keybindings, and MCP connections all carry over with no user action" (digitalapplied.com). The on-disk data dir is unchanged: `~/.codeium/windsurf/` still holds global MCP config; the JetBrains plugin is still "Windsurf for JetBrains." Sources: docs.devin.ai/desktop/changelog ("Windsurf is now Devin Desktop"); digitalapplied.com, hindsight.vectorize.io (COMMUNITY).
- **Cascade EOL (OFFICIAL + COMMUNITY):** Cognition's documentation states Cascade "remains available through July 1st" (webdeveloper.com); the replacement is **Devin Local**, a from-scratch Rust rewrite Cognition states is "up to 30% more token-efficient" with parallel subagents (webdeveloper.com) — treat the efficiency figure as vendor-stated until independent benchmarks land (digitalapplied.com, COMMUNITY).
- **(a) Repo-local skills — VERIFIED (OFFICIAL).** Devin Desktop's in-session skill tool discovers skills under `.windsurf/skills/`, `.agents/skills/`, and `.claude/skills/` (matching `devin skills list`), now also resolving symlinked dirs. Format: SKILL.md. Committable path: `.windsurf/skills/` or `.agents/skills/`. Source: docs.devin.ai/cli/changelog/stable.
- **(b) Native hooks — VERIFIED (OFFICIAL).** Workspace-level hooks load from `.windsurf/hooks.json` at the opened folder. Events: `pre_user_prompt`, `pre_read_code`, `post_read_code`, `pre_write_code`, `post_write_code`, `pre_run_command`, `post_run_command`, `pre_mcp_tool_use`, `post_mcp_tool_use`, `post_setup_worktree`. **Blocking:** only pre-hooks (`pre_user_prompt`, `pre_read_code`, `pre_write_code`, `pre_run_command`, `pre_mcp_tool_use`) can block, via exit code 2; post-hooks cannot block. Three config levels (system/global/workspace). Devin changelog confirms `pre_user_prompt` exit-2 blocking and a Windsurf→Devin hook migration command. Sources: docs.windsurf.com/windsurf/cascade/hooks (OFFICIAL); docs.devin.ai/desktop/changelog-next.
- **(c) PROJECT-scoped MCP — NOT SUPPORTED / ABSENT (OFFICIAL).** MCP config is the user-global `~/.codeium/windsurf/mcp_config.json` (unchanged by the rebrand; stdio/Streamable HTTP/SSE, OAuth, `${env:VAR}`/`${file:/path}` interpolation). No committable per-repo MCP file exists. Sources: docs.devin.ai/desktop/cascade/mcp (OFFICIAL); hindsight.vectorize.io (COMMUNITY). The separate *Devin CLI* does support project MCP (§7) but is a distinct binary.

### 3. CLINE (VS Code extension / JetBrains / CLI / SDK)
Reads `.clinerules` (file or `.clinerules/` dir) for project rules; rules picked up automatically by CLI, VS Code extension, and JetBrains plugin. Source: github.com/cline/cline; docs.cline.bot.
- **(a) Skills — VERIFIED (OFFICIAL).** Project skills: `.cline/skills/` (committable); global: `~/.cline/skills/` (also `~/Documents/Cline/`). Source: docs.cline.bot/cline-cli/configuration.
- **(b) Native hooks — VERIFIED (OFFICIAL).** Project hooks: `.cline/hooks/`; global: `~/.cline/hooks/` (or `~/Documents/Cline/Hooks/`). Must be enabled via `cline config` → `hooks-enabled`; "run at key points in Cline's workflow." SDK plugin system also registers tools + lifecycle hooks programmatically. Sources: docs.cline.bot/cline-cli/configuration; docs.cline.bot/customization/hooks.
- **(c) PROJECT-scoped MCP — NOT SUPPORTED (OFFICIAL).** MCP lives in user-global `~/.cline/data/settings/cline_mcp_settings.json` (VS Code extension: `.../globalStorage/saoudrizwan.claude-dev/settings/cline_mcp_settings.json`). CLI and extension share this format; the documented `.cline/` repo tree lists rules/skills/hooks/agents/plugins/cron but **no MCP file**. Feature request cline/cline Discussion #2418 confirms project-level MCP is not yet supported; workarounds are `.clinerules` tool-scoping or `CLINE_DIR`/`--config` pointing at a per-project config dir. Sources: docs.cline.bot/cline-cli/configuration (OFFICIAL); github.com/cline/cline/discussions/2418 (COMMUNITY).

### 4. HERMES (Hermes Agent by NousResearch)
**Identity — RESOLVED (OFFICIAL):** general autonomous agent runtime (`hermes-agent`), not a coding-only IDE. Source: hermes-agent.nousresearch.com; github.com/NousResearch/hermes-agent.
- **(a) MCP config + schema — VERIFIED (OFFICIAL).** Declared in user-global `~/.hermes/config.yaml` under `mcp_servers:` (YAML, not JSON). Local example: `mcp_servers:` → `filesystem:` → `command: "npx"`, `args: ["-y","@modelcontextprotocol/server-filesystem","/tmp"]`. Remote servers use `url:` + `headers:` (or `auth: {type: oauth}`); supports `timeout`, `allowed_tools` filtering, stdio + HTTP/SSE, mTLS (`client_cert`/`client_key`). CLI: `hermes mcp add/remove/list/test/configure`, `/reload-mcp`. User-global only; no per-repo file documented. Source: github.com/NousResearch/hermes-agent (docs/user-guide/features/mcp.md); hermes-agent.nousresearch.com/docs/user-guide/features/mcp.
- **(b) Hooks vs cron — VERIFIED: real event hooks exist (OFFICIAL).** Hooks live in `~/.hermes/hooks/<name>/` with a `HOOK.yaml` manifest (`events:` list) + `handler.py`. Documented events include `agent:end`, `on_session_start`, `on_session_end`, `pre_llm_call`, `post_llm_call`, and pre-tool-call hooks (a security deep-dive documents "pre-tool-call hooks require analyst confirmation … before execute_command or containment MCP calls fire," i.e. gate/block capability). Cron (`cron/jobs.yaml`, `cron/scheduler.py`) is a *separate* scheduled-prompt mechanism, not the hook system. So edit-time/lifecycle hooks are SUPPORTED. Sources: hermes-agent.nousresearch.com/docs/developer-guide/plugins (OFFICIAL); kenhuangus.substack.com (COMMUNITY).

### 5. GEMINI CLI (Google)
- **(a) Lifecycle hooks — VERIFIED (OFFICIAL).** First-class hook system (beyond `--checkpointing`), configured in `settings.json` under a `hooks` object. **Project-scoped committable file: `.gemini/settings.json`** (merged with user `~/.gemini/settings.json`, system, and extension layers; project wins). Per the Google Developers Blog, "Hooks are enabled by default in Gemini CLI as of v0.26.0+." Events: `SessionStart`, `SessionEnd`, `BeforeAgent`, `AfterAgent`, `BeforeModel`, `AfterModel`, `BeforeTool`, `AfterTool`, `Notification`. **Blocking = YES:** a `BeforeTool` hook returns `{"decision":"deny","reason":"..."}`; per geminicli.com/docs/hooks/reference, "Exit Code 2 (Block Turn): Aborts the turn and skips the LLM call." Matchers are regex (tools) / exact strings (lifecycle); CLI mgmt via `/hooks` panel and `gemini hooks install/uninstall/migrate --from-claude`; provides `GEMINI_PROJECT_DIR` and `CLAUDE_PROJECT_DIR` alias. Sources: github.com/google-gemini/gemini-cli (docs/hooks/index.md, reference.md); developers.googleblog.com "Tailor Gemini CLI to your workflow with hooks." **Unification note:** the new Antigravity CLI replaces Gemini CLI and uses the Antigravity `hooks.json` model (§1a); the `google-gemini/gemini-cli` hook system remains documented for the standalone Gemini CLI.

### 6. PI (earendil-works/pi — by Mario Zechner / "badlogic")
**Identity — RESOLVED (OFFICIAL):** open-source terminal coding agent (`pi-mono`), the runtime under OpenClaw. NOT Inflection's Pi chatbot; unrelated to Raspberry Pi. Deliberately minimal — per Dan MacKinlay (danmackinlay.name), "pi's entire system prompt plus its four tools (read, bash, edit, write) come in under 1000 tokens, on the argument that frontier models are RL-trained enough to already know what a coding agent is." Sources: github.com/earendil-works/pi; aibuilderclub.com, danmackinlay.name (COMMUNITY).
- **(a) Skills — REVERSE the "no skills" premise (OFFICIAL).** pi implements the Agent Skills standard and auto-discovers skills from `.agents/skills/` (cwd + ancestors up to git root), package `skills/` dirs, and configured external dirs (`~/.claude/skills`, `~/.codex/skills`); project-level Claude skills can be added via `.pi/settings.json`. Disable with `--no-skills`. So skills are **SUPPORTED** (repo-scoped `.agents/skills/`), not absent — pi reuses the cross-agent standard rather than a bespoke path. Sources: github.com/earendil-works/pi (packages/coding-agent/docs/skills.md); pi.dev/docs/latest/skills.
- **(b) Core hook framework — ABSENT as a hooks file; extensions instead (OFFICIAL).** pi has no Claude-Code-style out-of-process `hooks.json`. Lifecycle-event subscription is done through TypeScript **extensions** (`.ts` files in an `extensions/` dir) that "subscribe to lifecycle events, register custom tools, add commands" via `ExtensionAPI`. If "core hook framework" means a vendor JSON/TOML hook file, that is **NOT SUPPORTED**. MCP is unsupported in core by design (per task, not researched). Sources: github.com/parmalla/pi-coding-agent-skills; earendil-works/pi docs.

### 7. DEVIN (Cognition — cloud Devin + Devin CLI/"Devin for Terminal"; distinct from Devin Desktop §2)
"Devin" spans cloud SaaS (docs.devin.ai/work-with-devin), Enterprise VPC, and a **Devin CLI / "Devin for Terminal"** (cli.devin.ai). These have different surfaces.
- **(a) Repo-local edit-time hooks — SPLIT (OFFICIAL).** *Cloud Devin:* no repo-local edit-time hooks — automation is via trigger integrations (Slack, Linear, API/playbooks/schedules) → local hooks **NOT SUPPORTED**. *Devin CLI:* committable lifecycle hooks exist — `.devin/hooks.v1.json` ("Lifecycle hooks (Claude Code compatible)"), and `.devin/config.json` supports a `hooks` key → **SUPPORTED**. Sources: docs.devin.ai/cli/extensibility; docs.devin.ai/cli/extensibility/configuration.
- **(b) Inbound MCP config — SPLIT (OFFICIAL).** *Cloud Devin:* MCP is UI/marketplace-only (Settings → Connections → MCP servers / MCP Marketplace / "Add a custom MCP") — **no project config file**, so a speculative `.devin/config.json` for cloud Devin can be **retired**. Sources: docs.devin.ai/work-with-devin/mcp; cognition.com/blog/mcp-marketplace. *Devin CLI:* a committable MCP file **DOES** exist — `.devin/config.json` with an `mcpServers` object (stdio `command`/`args`/`env` or remote `url`+`transport:http`); personal keys in gitignored `.devin/config.local.json`; user-global `~/.config/devin/config.json` (`%APPDATA%\devin\config.json` on Windows). Project configs support `permissions`, `mcpServers`, `read_config_from`, `hooks`. Sources: docs.devin.ai/cli/extensibility/mcp/configuration; docs.devin.ai/cli/reference/configuration/config-file. **Conclusion:** retire `.devin/config.json` for *cloud* Devin only; keep it for *Devin CLI*.

### 8. SWIVAL (github.com/Swival/swival — open-source CLI coding agent)
**Identity — RESOLVED (OFFICIAL):** small pure-Python CLI coding agent optimized for open/local models. Source: swival.dev.
- **(a) Project-instruction filename — VERIFIED (OFFICIAL).** Loads `CLAUDE.md` (project rules, base dir only, ≤10k chars) and `AGENTS.md` (project root + user `~/.config/swival/AGENTS.md` + cross-agent `~/.agents/AGENTS.md`). Primary committable project file: **`AGENTS.md`** at repo root (also `CLAUDE.md`). `/init` generates a project `AGENTS.md`; `/remember` appends conventions. Source: swival.dev/pages/customization.html.
- **(b) MCP config + schema — VERIFIED (OFFICIAL).** Precedence: `--no-mcp` > `--mcp-config FILE` (explicit JSON) > `swival.toml [mcp_servers.*]` (project TOML) > `.swival/mcp.json` (project JSON). Repo-scoped committable options: **`.swival/mcp.json`** or a `[mcp_servers.*]` table in project `swival.toml`. Transports: stdio + SSE; tools namespaced `mcp__<server>__<tool>`. Source: swival.dev/pages/mcp.html.
- **(c) Lifecycle hooks — VERIFIED but LIMITED (OFFICIAL).** Only **startup and exit** hooks, via the `lifecycle_command` config key (single command at session start/exit, intended to sync `.swival/` state to remote storage; `lifecycle_fail_closed` raises `LifecycleError`). **No edit-time / per-tool gating hooks.** A separate **Command Middleware** (`command_middleware` key) can rewrite/block shell commands pre-execution — the closest thing to edit-time gating. Sources: swival.dev/pages/lifecycle-hooks.html; swival.dev/pages/customization.html; swival.dev/pages/command-middleware.html.

### 9. CODEWHALE (github.com/Hmbown/CodeWhale — terminal coding agent for DeepSeek/open models)
**Identity — RESOLVED (OFFICIAL):** open-source Rust terminal agent; canonical command `codewhale` (legacy `deepseek`/`deepseek-tui` shims). Config at `~/.codewhale/` (legacy `~/.deepseek/` still read). Sources: codewhale.ai/docs.html; codewhale.net/en/faq.
- **(a) Hook events + blocking — VERIFIED (OFFICIAL).** Two surfaces:
  1. **Lifecycle hooks** in `config.toml` under `[hooks]` / `[[hooks.hooks]]` — 8 events: `session_start`, `session_end`, `message_submit`, `tool_call_before`, `tool_call_after`, `mode_change`, `on_error`, `shell_env` (the special `shell_env` event injects env vars into shell calls from stdout `KEY=VALUE` lines; its failure does not abort the call). `[hooks].enabled` + `default_timeout_secs`. Source: github.com/Hmbown/CodeWhale/blob/main/config.example.toml (`[hooks]` section enumerates all 8); codewhale.ai/docs.html.
  2. **Approval-gated tool hooks** — a **`.codewhale/hooks.toml`** system that can **allow / deny / ask** before any tool call (this is the blocking contract), combined with the exec policy (run / needs-approval / forbidden). Source: lib.rs/crates/codewhale-agent (".codewhale/hooks.toml hook system can allow, deny, or ask before any tool call"). **Blocking = YES** via `.codewhale/hooks.toml`. Committable repo-scoped hook file: **`.codewhale/hooks.toml`**; lifecycle `[hooks]` table can live in project `.deepseek/config.toml`.
- **Bonus (OFFICIAL):** MCP via `~/.deepseek/mcp.json` (`mcp_config_path`; user-global, `mcpServers` object); skills at `~/.deepseek/skills/<name>/SKILL.md`; instructions via `AGENTS.md` + `.codewhale/constitution.json`; project `.deepseek/config.toml` replaces the user-level `instructions` array wholesale.

### 10. CURSOR (Anysphere)
- **(a) Auto-discovered SKILLS directory — VERIFIED PRESENT (OFFICIAL) — REVERSES the "skills NOT SUPPORTED" hypothesis.** Cursor documents an auto-discovered skills dir implementing the open Agent Skills standard. Both scopes are official: per Ajit Singh (singhajit.com), "Put skills in `.cursor/skills/` to share them through Git, or `~/.cursor/skills/` to keep them personal across every project." Repo-scoped committable path: **`.cursor/skills/<name>/SKILL.md`** (category subfolders allowed; skills appear in the `/` slash menu; `disable-model-invocation: true` makes a skill manual-only; Cursor 2.4+ ships `/migrate-to-skills`). This is in addition to `.cursor/commands/` (custom commands), `.cursor/rules/*.mdc` (rules), `.cursor/hooks.json` (hooks), and `.cursor/mcp.json` (project MCP). Sources: cursor.com/docs/skills (OFFICIAL); singhajit.com, agensi.io (COMMUNITY path detail). **Mark skills = SUPPORTED (settled: `.cursor/skills/`).**

## Recommendations
1. **Antigravity:** graft everything into `.agents/` — hooks (`hooks.json`), rules (`rules/*.md`), skills (`skills/`), MCP (`mcp_config.json`), all committable. Verify the `trigger: always_on` frontmatter key in-product (community-corroborated, not verbatim official). If you support the Antigravity *CLI* variant, do not rely on project-local MCP (issue #60) — fall back to `~/.gemini/config/mcp_config.json`.
2. **Devin Desktop & Cline:** mark project-scoped MCP as **NOT SUPPORTED** (both user-global); do not synthesize a committable MCP path. For instructions/skills/hooks, target `.devin/`|`.windsurf/` (Desktop) and `.clinerules`/`.cline/` (Cline).
3. **"Devin" axis:** split into cloud Devin (marketplace MCP + trigger-only, no local file) vs Devin CLI (`.devin/config.json` `mcpServers` + `.devin/hooks.v1.json`). Retire the speculative `.devin/config.json` only for the cloud product.
4. **pi & Cursor:** REVERSE prior "skills NOT SUPPORTED" markings — target `.agents/skills/` (pi) and `.cursor/skills/` (Cursor). For pi hooks, use TypeScript extensions, not a hooks file.
5. **Swival:** mark lifecycle hooks as startup/exit-only (no edit-time gate); use command middleware (`command_middleware`) for pre-command blocking. Instructions → `AGENTS.md`; MCP → `.swival/mcp.json`.
6. **CodeWhale:** blocking hooks → `.codewhale/hooks.toml` (allow/deny/ask); the 8-event lifecycle set → `config.toml [hooks]`; MCP is global (`~/.deepseek/mcp.json`).
7. **Gemini CLI:** hooks + MCP both live in the committable `.gemini/settings.json`.

**Benchmarks that would change these calls:** (a) if Antigravity CLI issue #60 is fixed, project-local CLI MCP becomes usable; (b) if Cline Discussion #2418 or a Devin Desktop release ships a per-repo MCP file, flip those two from NOT SUPPORTED; (c) re-verify all Devin Desktop paths after the July 1, 2026 Cascade EOL, since Devin Local may change hook/skill discovery.

## Caveats
- Narrative/identity details for Devin Desktop (rebrand date, Rust rewrite, 30% efficiency) and pi (authorship, token budget) are COMMUNITY-sourced; the 30% figure is vendor-stated and unbenchmarked. All primary config paths are OFFICIAL.
- Antigravity CLI project-local MCP (`.antigravitycli/mcp_config.json`) may be silently ignored (issue #60); the IDE/SDK `.agents/mcp_config.json` is reliable.
